# 01 · 对标调研：生物样本库与成熟数据基础设施

> 目的：为「医学生人才信息库」提炼**可移植设计模式**，回答"借鉴什么、怎么落地"。
> 纪律：只采信可访问的一手文档；查不到的明确标注「未证实」。与 `docs/01-数据模型设计.md` 互补——本文给证据与模式，那份给落位。

---

## 0. 结论

UKB Showcase 的价值不在"它存了什么"，而在**把观测型数据库的全部可变性外化成四张元数据表：目录 + 编码表 + 派生层 + 字段级访问策略**。人才库 v0.1 骨架方向正确，缺的正是这四者"可下载、可版本化、可被策略查询"的形态。

## 1. UK Biobank Showcase

### 1.1 导航与清单

主导航为 Index / Browse / Search / Catalogues / Downloads / Login(AMS) / Help（[schema.cgi?id=1](https://biobank.ndph.ox.ac.uk/showcase/schema.cgi?id=1)）。Catalogues（[catalogs.cgi](https://biobank.ndph.ox.ac.uk/showcase/catalogs.cgi)）下辖 **7 个清单**：Fields、Categories、**Returns（研究者返回的派生/增强数据集）**、Publications、Resources、**Record tables（整表形态）**、Schema（Showcase 自身元信息 schema）。

> 要点：**"字段"与"返回物"是并列的一级清单**——派生资产不是附注，是有目录的一等公民。

### 1.2 Category 分类树

`browse.cgi` 返回真实多级树（[browse.cgi](https://biobank.ndph.ox.ac.uk/showcase/browse.cgi?id=1&cd=schema)）：7 个顶层大类（Population characteristics 38、Assessment centre 5301、Additional exposures 367、Health outcomes 2655 等）；每节点带 **`tree_subtree_total`（子树字段数）与 `tree_node_total`（直属字段数）** 两个计数，支持展开到第 N 级。实测深度 5–6 级，例：`Assessment centre(5301) → Touchscreen(396) → Lifestyle and environment(155) → Physical activity(36) → MET Scores(9)`。分类节点自身有稳定 id（如 `label.cgi?id=100054`）。

> 要点：**分类是独立实体（有 id、父子、计数），不是字段上的字符串标签。**

### 1.3 field 的组织方式：Schema 1 的 27 属性

UKB 把"字段元数据"本身做成了可下载 schema。**Schema 1「Data field properties」**（[schema.cgi?id=1](https://biobank.ndph.ox.ac.uk/showcase/schema.cgi?id=1)）列出 27 个属性，本次调研信息量最大的一页。核心项：

| 属性 | 取值（原文） |
|---|---|
| `field_id` / `title` | 稳定 ID / 标题 |
| `available` | 0 full / 1 view-only / 4 retired |
| `stability` | 0 complete / 1 updateable / 2 accruing / 3 variable |
| `private` | 0 public / 1 restricted |
| `value_type` | 11 int, 21 single choice, 22 multi choice, 31 real, 41 string, 51 date, 61 time, 101 compound, 201 blob |
| `base_type` | 0 see value type, 11 int, 31 real, 41 string, 51 date |
| `item_type` | 0 data, 10 sample, 20 bulk, 30 record |
| `strata` | 0 primary, 2 auxiliary, 3 derived |
| `instanced` | 0 no / 1 defined / 2 variable |
| `arrayed` | 0 no / 1 yes |
| `sexed` | 0 unisex / 1 male / 2 female |
| `units` / `main_category` / `encoding_id` | 单位 / 主分类 / 编码表 ID |
| `instance_id` / `instance_min` / `instance_max` | 实例（访问） |
| `array_min` / `array_max` | 数组边界 |
| `notes` / `debut` / `version` / `num_participants` / `item_count` / `showcase_order` / **`tier`** | 备注/首发/版本/有数据人数/条目数/展示序/**成本层级** |

**四个正交结构维度在此定型**，是 UKB 最核心的抽象：

- **instance（实例）**：同字段的多次采集（多次随访/到访），`0 无 / 1 固定 / 2 可变`；
- **array（数组）**：同一次采集内的多个重复值（多种用药、多个手术）；
- **encoding（编码）**：取值含义外挂编码表，字段只存 code；
- **field_id**：跨 instance/array 不变的稳定语义锚点。

> 因此 UKB 的"值"实际主键是 **`field_id × instance × array`**：field 是一列语义，数据是它的笛卡尔展开。

### 1.4 字典下载

Schema 页提供机器可读双格式下载与 wget 命令（[schema.cgi?id=1](https://biobank.ndph.ox.ac.uk/showcase/schema.cgi?id=1)）：

```
wget -nd -O field.txt "biobank.ndph.ox.ac.uk/ukb/scdown.cgi?fmt=txt&id=1"   # tab separated
wget -nd -O field.xml "biobank.ndph.ox.ac.uk/ukb/scdown.cgi?fmt=xml&id=1"   # pseudo-XML
```

> **数据字典是可 wget、可版本化、双格式的产物，不是网页**——能进版本控制、能 diff、能被程序消费。

### 1.5 访问分级：两套体系并存

UKB 目前同时运行两套控制（[tiered-access](https://uk-biobank.gitbook.io/data-access-guide/readme/tiered-access.md)）：

1. **旧制 basket + MTA**：按"数据篮"逐字段批准，老项目沿用；
2. **新制 Tier 1/2/3 + 新 MTA**：新申请按整体层级授权。

新制的精细处在于**每个 Data-Field 携带 Cost Tier 编码 `dN1 oN2 sN3`**，各 Ni ∈ {1,2,3,X}：`d`=从 RAP 下载、`o`=RAP 在线查看、`s`=从 Showcase 下载（主数据集/下载工具/Data Portal）；数字为该访问方式所需的**最低 Tier**，`X`=不可用。官方例：Data-Field 20158（DXA 图像）= **`d3 o2 s3`**，即 Tier 2 及以上可在线看，但只有 Tier 3 能下载。

> **访问策略是"字段级 × 访问方式级"的乘积**，同一字段"看"与"拿"门槛可不同——比"四档分类"精细得多。

### 1.6 派生与编码（实证）

- **派生有显式位**：`strata = 3 derived`。Browse 的 Health outcomes 支下实测可见两类派生产品：**Algorithmically-defined outcomes**（`label.cgi?id=42`，38 个：Stroke `43`、Myocardial infarction `44`、Asthma `45`、COPD `46`、Dementia `47`、ESRD `48`、MND `49`、Parkinson's `50`）与 **First occurrences**（`label.cgi?id=1712`，子树 2330 字段，按 ICD-10 章节组织 `2401`–`2417`，每章 48–346 字段）。
- **编码**：Schema 有 `encoding_id` 位；`value_type` 的 `21 single choice / 22 multi choice` 正是"外挂编码表"的取值形态。
- **版本与质量**：字段级 `version` + `debut`；`stability` 四态区分"定义是否还会变"；`num_participants` 给出实际有数据人数；Browse 中可见专门 QC 分类（如 `label.cgi?id=100116`「Quality control measures for OCT」）。

### 1.7 取数方式（部分未证实）

可实证：Showcase 的 `Login` 指向 AMS（`ams.ukbiobank.ac.uk/ams/resApplications`）；`available=1 view-only` 与 tier 编码的 "online on the RAP" 共同指向 **RAP** 为分析环境；`ukbfetch` 为 Showcase 下载工具（[tiered-access](https://uk-biobank.gitbook.io/data-access-guide/readme/tiered-access.md)）；Catalogues 另有 **Record tables**。

> **未证实**：Table Exporter 界面与限制、AMS 申请字段全集、RAP 技术规格、`dxdata` 命令语义、returns/refresh 发布日历——本次未取到官方页，建议以 AMS 用户指南与 RAP 文档二次核验后再写入设计。

## 2. 横向对标

**NHANES（公开下载 + 文件级文档 + 抽样权重）**：CDC 官方教程设独立的 **Weighting 模块**（[weighting.aspx](https://wwwn.cdc.gov/nchs/nhanes/tutorials/weighting.aspx)），示例明确"做什么分析用什么权重"（如 phlebotomy 权重 `wtph2yr`）；官方 FAQ 与 codebook 体系见 [NCHS NHANES FAQ](https://wwwn.cdc.gov/NCHS/NHANES/ContinuousNhanes/faq.aspx)。启示不在"权重"本身，而在**每个数据文件自带说明文档，且分析方法（加权）是文档的一部分**。*（教程各模块逐条原文未取得——两次抓取 404/截断，故不引模块编号。）*

**All of Us（Workbench + Data Browser + 分层访问）**：分发形态是 **Researcher Workbench**（云端分析，"数据不出云"）配 **Data Browser**（可浏览数据目录），并有 **Registered Tier / Controlled Tier** 之分，官方维护按版本迭代的 **Controlled CDR Directory**（[Workbench 事实表](https://ictr.wisc.edu/wp-content/uploads/2026/07/Researcher-Workbench-Digital-Fact-Sheet_Digital.pdf)、[Controlled CDR Directory](https://support.researchallofus.org/hc/en-us/articles/29475233432212-Controlled-CDR-Directory)、[获取 Workbench 访问](https://www.orau.gov/hsc/nlm/All-of-Us/GainingAccessToTheResearcherWorkbench.pdf)）。**未证实**：两档逐项数据内容差异、Data Browser 字段筛选能力（官方页 403 / 内容类型不支持）。

**CHARLS（注册即取 + 文档三件套）**：官方 FAQ（[CHARLS FAQ](http://charls.pku.edu.cn/en/Faq/Frequently_Asked_Questions.htm)）给出可实证流程——注册（签协议+真实信息审核）→ 按数据集分别申请 → **3 个工作日**审批；**STATA 格式**交付；**每轮发布配套「用户指南 + 问卷 + codebook」**，官方要求分析前先读；每轮实地结束后**约 1 年**发布；官方维护 Data Forum。这是**最贴近人才库资源条件的样板**。

**dbGaP / EGA（受控访问）**：个体级数据不外发，授权须签署 **Data Use Certification Agreement**（[dbGaP DUC phs001554](https://dbgap.ncbi.nlm.nih.gov/aa/wga.cgi?view_pdf&stacc=phs001554.v1.p1)、[phs001524](https://dbgap.ncbi.nlm.nih.gov/aa/wga.cgi?view_pdf&stacc=phs001524.v1.p1)）并声明研究用途；EGA 侧有独立访问体系与安全说明（[EGA Security Overview](https://www.ega-archive.org/assets/files/European_Genome_phenome_Archive_Security_Overview.pdf)）。映射到人才库即 T2/T3 的完整生命周期：**申请→审查→签署使用条款→授权期内可访问→到期回收**，而非一个 `access_tier` 字段。**未证实**：dbGaP DAC 审批时限、EGA DAC 组织流程。

**OMOP CDM（`source_value` + 映射血缘）**：v5.4 规范（[cdm54.html](https://ohdsi.github.io/CommonDataModel/cdm54.html)）在**每张事件表同时保留三件套**：`xxx_source_value`（"store the verbatim value from the source data"，明确 "not intended for use in standard analytics but for reference only"）、`xxx_source_concept_id`（源词表概念）、`xxx_concept_id`（标准概念，"recommended for primary use in analyses"）。另有 `*_type_concept_id` **专载 provenance**："This field can be used to determine the provenance of the record, as in whether the condition was from an EHR system, insurance claim, registry, or other sources"。规范中还有 `SOURCE_TO_CONCEPT_MAP`（词表映射）、`CONCEPT_ANCESTOR`（层级闭包）、`CONCEPT_RELATIONSHIP`、`METADATA`、`CDM_SOURCE`。`OBSERVATION_PERIOD` 更把统计纪律显式建模："absence of records indicate such Events did not occur during this span of time"，且 "Events may exist outside all of the time spans"。**给人才库的两条**：原文与标准码并存永不丢原文；"数据从哪来"是有词表的概念，不是布尔 flag。

**元数据标准（Croissant 已证实；DDI/DCAT 未证实）**：**Croissant 1.0**（[规范](https://docs.mlcommons.org/croissant/docs/croissant-spec.html)）是 MLCommons 发布、基于 **JSON-LD + schema.org/Dataset** 的数据集描述格式。顶层要求 `@context`/`@type`/`dct:conformsTo`/`description`/`license`/`name`/`url`/`creator`/`datePublished`；资源层 `cr:FileObject`（`contentUrl`/`encodingFormat`/`sha256`/`containedIn`）与 `cr:FileSet`（`includes`/`excludes` glob）；结构层 `cr:RecordSet`（含 `key`）+ `cr:Field`（`dataType`/`source`/`references`/`repeated`/`subField`），其中 `references` 原文即 "the equivalent of a foreign key reference in a relational database"；行级血缘由 `Field.source` 的 `extract`（`column`/`jsonPath`/`fileProperty`）+ `transform`（`delimiter`/`regex`/`jsonQuery`）+ `format` 描述**每个值是怎么从文件变出来的**；版本推荐 SemVer `MAJOR.MINOR.PATCH` 且各段语义明确（PATCH 仅序列化变化；MINOR 可追加字段/RecordSet 而旧集合仍可取；MAJOR 为破坏性），配 `sha256` 校验与 `isLiveDataset` 活数据集标记。**未证实**：DDI 元素清单（`var`/`varGrp`/`nCube`）、W3C DCAT 类与属性、二者与 Croissant 的映射——搜索仅返回会议材料与二手 PDF，未取到官方规范页。

## 3. 12 条可移植设计模式

**统一约定**：新表建在 `mt` schema；命名沿用 `docs/01-数据模型设计.md` 的 ID 前缀规范。

**P1 · 字段目录独立成表且语义元数据完备**
- 原始：UKB Schema 1 的 27 属性（[schema.cgi?id=1](https://biobank.ndph.ox.ac.uk/showcase/schema.cgi?id=1)）。
- 落地：扩 `mt.field_catalog`，补四组列——结构组 `is_arrayed BOOLEAN`、`array_min/max SMALLINT`、`instance_role`（应届/规培期/在职）；风险组 `stability`（complete/updateable/accruing/variable）；取值组 `value_type`、`base_type`；可见性组 `is_private`、`debut_version`、`showcase_order`。

**P2 · 分类树独立成实体并带双向计数**
- 原始：Category 有独立 id、父子关系，节点带 `tree_subtree_total`/`tree_node_total`，支持展开到第 N 级（[browse.cgi](https://biobank.ndph.ox.ac.uk/showcase/browse.cgi?id=1&cd=schema)）。
- 落地：新建 `mt.category_node(category_id, parent_id, level, name_zh, name_en, subtree_field_count, node_field_count, sort_order, status)`；`field_catalog` 增 `main_category_id`。计数用物化视图刷新。收益：新增分类不动表结构。

**P3 · 一个字段 = 语义锚点，值 = `field × instance × array`**
- 原始：`instanced`、`arrayed`、`instance_min/max`、`array_min/max`（[schema.cgi?id=1](https://biobank.ndph.ox.ac.uk/showcase/schema.cgi?id=1)）。
- 落地：**本项目最该修正的一处**。当前 `education_record`/`clinical_exposure`/`preference` 各自建表、语义分散。增统一值表 `mt.field_value(field_id, subject_type, subject_id, instance_key TEXT, array_index SMALLINT, value_text, value_num, value_date, value_code, recorded_at)`，`instance_key` 承载"第几次采集/第几段经历"。保留现有实体表作主数据，让 `field_catalog` 新增字段**零 DDL** 落数。

**P4 · 编码表外挂 + 单选/多选类型区分**
- 原始：`encoding_id` 指向编码表；`value_type` 区分 `21 single choice`/`22 multi choice`。
- 落地：`code_table`/`code_value` 已在（`schema/sql/001_core_schema.sql` L119–150），补 `field_catalog.value_type` 决定"存一个 code 还是 code 数组"；把 ICD-10、Read code、ESCO、ISCO-08、《职业分类大典2022》的实际映射行落进 `code_value.external_mapping`，保留 `deprecated`/`replaced_by` 历史链。

**P5 · 派生层显式分层 + 两代派生产品并存**
- 原始：`strata = 0 primary / 2 auxiliary / 3 derived`；Browse 中 **Algorithmically-defined outcomes**（38）与 **First occurrences**（2330）并排为两类派生目录。
- 落地：`field_catalog` 增 `strata`；`derived_feature` 增 `derived_class ∈ {algo_outcome, first_occurrence, score, index}` 与 `catalog_category_id`。first-occurrence 语义对应 `skill_assertion.first_observed_at`：新增 `mt.first_occurrence(person_id, concept_id, first_date, source_field_id, algo_version)`，回答"此人何时首次具备 X"。

**P6 · 派生定义可 wget、可 diff、双格式**
- 原始：`scdown.cgi?fmt=txt|xml&id=1` + 明确 wget 命令。
- 落地：把 `schema/catalog/field_catalog.csv` 升级为**构建产物**：`make catalog` 从 `field_catalog`/`code_table` 导出 `dist/catalog/field_catalog.csv` + `code_tables/*.csv` + `schema.json`，计算 sha256 写入 `change_log`。字典能进 git、能 diff、能对客户交付。

**P7 · 访问策略 = 字段级 × 访问方式级（乘积而非标量）**
- 原始：Cost Tier 编码 `dN1 oN2 sN3`，`d`=RAP 下载、`o`=RAP 在线、`s`=Showcase 下载；数字为最低 Tier，`X` 禁用；例 20158 = `d3 o2 s3`（[tiered-access](https://uk-biobank.gitbook.io/data-access-guide/readme/tiered-access.md)）。
- 落地：`access_tier` 单列**不够**。新建 `mt.access_policy(object_type, object_id, action, min_tier)`，`action ∈ {browse, view_inline, export_row, export_aggregate, bulk_download}`，`min_tier ∈ {T0,T1,T2,T3}`。示例：`PII.full_name` 的 `view_inline=T3`、`export_row=X`（永不导出）；`job_posting.salary_*` 的 `view_inline=T1`、`bulk_download=T2`。由 `access_log` 校验实际行为是否合规。

**P8 · 原文与标准码并存 + 来源是有词表的概念（OMOP 三件套）**
- 原始：每表同时留 `xxx_source_value`（verbatim，仅供参照）、`xxx_source_concept_id`、`xxx_concept_id`（标准，供分析）；`xxx_type_concept_id` 载 provenance（[cdm54.html](https://ohdsi.github.io/CommonDataModel/cdm54.html)）。
- 落地：`education_record.major_raw`/`major_code` 已符合，推广到**所有**业务表（`employment_record.title_raw`/`title_normalized` 已有）；并把 `source_id` 旁挂 `CT_SOURCE_TYPE` 与 `CT_PROVENANCE_METHOD` 正式码，让"来自简历解析还是本人填报"成为**可聚合维度**，而不只是审计信息。

**P9 · 映射血缘表 + 层级闭包表**
- 原始：`SOURCE_TO_CONCEPT_MAP`、`CONCEPT_ANCESTOR`（避免递归查询）、`CONCEPT_RELATIONSHIP`、`METADATA`、`CDM_SOURCE`。
- 落地：新建 `mt.concept_mapping(source_code_table_id, source_code, target_concept_id, mapping_type, confidence, valid_from, valid_to, created_by)`——"临床医学（五年制）"→`con_临床医学` 的映射留痕、可审计、可多对一。再由 `concept_relation` 物化 `mt.concept_ancestor(ancestor_id, descendant_id, min_levels, max_levels)`，使"统计所有外科子类专业"变成一次 join。

**P10 · 观测期建模：只在有数据的时间窗内推断"未发生"**
- 原始：`OBSERVATION_PERIOD` 明确 "absence of records indicate such Events did not occur during this span of time"，且事件可落在窗口之外。
- 落地：**人才库最易出统计错误处**。新建 `mt.observation_window(person_id, window_type, start_date, end_date, source_id)`，`window_type ∈ {resume_coverage, platform_active, followup}`。任何"此人没有 X"必须落在窗口内，否则只能表述为"未记录"。`gap_analysis` 与匹配引擎的缺口判定须前置查窗口。

**P11 · 数据集描述采用 JSON-LD + SemVer + sha256**
- 原始：Croissant 用 `cr:RecordSet`/`cr:Field` 描述表与列，`Field.references` 作外键、`Field.source` 记血缘；SemVer 各段语义明确；`sha256` 校验；`isLiveDataset` 标记活数据集（[规范](https://docs.mlcommons.org/croissant/docs/croissant-spec.html)）。
- 落地：`dist/catalog/dataset.jsonld` 输出 `@type: sc:Dataset`，`distribution` 指向导出 CSV，`recordSet` 对应 `person`/`skill_assertion`/`job_posting`，`field` 对应 `field_catalog` 行，`references` 从 FK 自动生成，`sha256` 从导出文件计算。**版本语义直接抄**：`field_catalog.version` 的 MINOR = 只加字段不改语义（正好对应 G3"加字段 ≤30 分钟不破坏既有数据"），MAJOR = 破坏性变更。

**P12 · 轻量注册 + 明确 SLA + 文档三件套**
- 原始：CHARLS 注册→按数据集申请→**3 个工作日**审批→STATA 交付；**每轮配套「用户指南+问卷+codebook」**；实地结束后约 **1 年**发布；官方 Data Forum 答疑（[CHARLS FAQ](http://charls.pku.edu.cn/en/Faq/Frequently_Asked_Questions.htm)）。NHANES 对应"每文件自带文档、方法写进文档"（[Weighting](https://wwwn.cdc.gov/nchs/nhanes/tutorials/weighting.aspx)）。
- 落地：建 `mt.dataset_release(release_id, name, version, published_at, next_expected_at, doc_guide_uri, doc_codebook_uri, doc_instrument_uri, checksum_sha256, access_policy_id)`；T1 申请走"注册→电子协议→3 工作日复核"。**纪律：没有 codebook 的数据集不允许发布。**

## 4. 差距清单（按优先级）

| 级别 | 差距 | 模式 | 动作 |
|---|---|---|---|

| P1 | 映射无独立血缘表 | 9 | 新建 `concept_mapping` + `concept_ancestor` |
| P2 | 数据字典靠人维护，非构建产物 | 6,11 | `make catalog` 导出 CSV + JSON-LD + sha256 |
| P2 | 无对外数据集发布登记 | 12 | 新建 `dataset_release` |
