## 1. 对标对象与选择理由

| 对象 | 为什么对标它 | 与本项目的相似性 |
|---|---|---|
| **UK Biobank** | 观测型数据库的元数据工程标杆：字段字典、分类树、实例/数组、字段级访问策略 | 同为"长期观测 + 多来源 + 分级访问" |
| **OMOP CDM** | 异构来源归一化的字段纪律（原文与标准码并存、来源即概念、观测期） | 同为"多来源汇入统一模型" |
| **Croissant 1.0** | 数据集描述的机器可读格式（JSON-LD + SemVer + sha256） | 需要对外发布数据集 |
| **CHARLS** | 资源条件最接近的样板：注册式申请 + 文档三件套 + 3 工作日审批 | 非巨头团队可复制 |
| **NHANES** | 公开下载 + 文件级文档 + 加权分析纪律 | 对外发布数据的文档范式 |
| **All of Us / dbGaP / EGA** | 分级访问与数据使用协议（DUC）的完整生命周期 | 人才数据同样敏感 |
| **O*NET / ESCO / ISCO** | 岗位与能力的国际标准骨架 | 岗位侧分类与能力本体 |
| **CanMEDS / ACGME** | 医学能力框架，界定"可迁移能力"的权威来源 | 医学生能力刻画 |

## 3. 明确**不采纳**（及理由）

| 不采纳 | 理由 |
|---|---|
| 完整 Data Vault 2.0 / Anchor Modeling 全套 | 复杂度远超一期规模；只借其"不可变 + 加列不动上游"原则，用 `valid_from/valid_to/recorded_at` 时间切片替代 |
| 全面 EAV 化 | 查询性能与约束能力崩塌；采用"类型化列 + 受控扩展 + 统一值表"三层 |
| NHANES 抽样权重体系 | 本项目不是概率抽样调查；但**借用"每份数据自带说明文档"的纪律** |
| 差分隐私 | 当前数据规模与披露场景用 k-匿名（k≥5）+ 小样本抑制已足够，引入 DP 会显著损失可用性 |
| 直接照搬 O*NET 全量能力要素 | O*NET 面向美国职业体系；只采其**内容模型结构**与可迁移技能 2.B 分组，不照搬数值 |
| 直接照搬《职业分类大典》全表 | 大典偏传统职业，缺新兴岗位（医疗 AI、真实世界研究）；大典作主干，新兴岗位靠 `code_value` 扩展 |
| 采集求职者个人简历用于填充人才库 | 合规红线：个人数据必须来自本人授权 |

## 5. 与既有项目的对标（避免重复建设）

见 `research/00-既有资产盘点与复用判断.md`。三条结论：

1. **可复用**：`canonical-experience-v2`（原子活动 + 责任等级 + 证据强制）、`bullet-claim-v2`（表述↔证据分离）、`career.schema.json`（sourcedClaim）、四道门禁模块、`capability_tags` 与 `role_packs` 种子、`job_portal.py` / `job_evaluation.py` / `robots_check.py`。
2. **不能依赖**：`capability_tags` 与 `capability_taxonomy.tag_experience()` 契约不匹配（**标签功能实际失效**），复用前必须先修。
3. **完全新建**：字段级数据字典、代码表体系、schema 版本化与迁移、实体关系与去重键（DOI / 统一社会信用代码 / 岗位规范化链接）、**结构化存储与检索层**（既有项目没有任何数据库）。
4. **抓取现状**：既有 6 个门户全为北欧/国际渠道，`job_scraper/` 为空 —— **中国岗位采集从零建**。
