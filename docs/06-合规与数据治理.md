# 06 · 合规与数据治理方案

> 把 PIPL/GDPR 的条文义务翻译成**可执行的表、字段与作业**。落位指向 `schema/sql/001_core_schema.sql`（下称 001）与 `002_ukb_patterns.sql`（下称 002）中已存在的表；本文件新引入的对象统一冻结在 §11。
> 三条总原则：**元数据公开、数据受控、个体数据不外发**；**同意是属性不是前提**；**只写策略不执行的合规是装饰**。

## 2. 数据分级与分类（T0–T3，落到字段）

| 层 | 判定 | 具体字段举例 | 默认获取方式 |
|---|---|---|---|
| **T0 公开** | 不含自然人信息，或不可逆聚合 | `occupation.*`、`concept.*`、`code_value.*`、`field_catalog.*`、`job_posting.title_raw/city/salary_*`、`v_skill_demand`（无小样本） | 开放浏览/下载 |
| **T1 注册** | 脱敏后不可直接定位个人 | `person.subject_code`、`education_record.degree_level/school_name/gpa`、`skill_assertion.level/transferability/confidence`、`credential.credential_type/status`、`job_requirement.raw_text` | 注册 + 用户协议，可在线查看 |
| **T2 受控** | 可识别或原文级 | `person_demographics.birth_year/*`、`narrative.raw_ref/raw_sha256`、`evidence.uri`、`match_result.explanation`、`job_posting.raw_text_ref` | 授权 + 合规审查 + **数据不落地**（§4.3） |
| **T3 敏感** | 敏感个人信息 | `person_pii.*`、`person_demographics.health_limits`、`person_constraint.description`（体检/家庭/签证） | 单独同意 + `encryption_key_id` 加密 + 最小化 + 逐次审计 |

**为什么二者是敏感个人信息、必须单独同意**：`health_limits`（色觉异常、听力受限）在招聘语境下直接决定“能否报考某岗位”，泄露即造成就业歧视，属 PIPL 第 28 条与 GB/T 35273 明列的健康生理信息；`id_hash` 虽为 HMAC，但可与外部库碰撞后锁定自然人，且不可变更，泄露即长期身份盗用。二者因此**不进常规画像、不进 `match_run` 特征池**，采集单列同意项，展示按 `access_policy` 判为“可在线查看、不可导出”（`export_row` = X），逐次写 `access_log`。

## 3. 合法性基础与同意管理

`consent_record.purpose` 采用五个受控取值（001 的注释只列了前四个，`third_party_share` 为本次补入，代码表与 DDL 见 §11）：`matching`、`research_report`、`product_improve`、`publishing`、`third_party_share`。设计要点：

1. **一用途一记录**：`revoked_at IS NULL` 即有效；判权限按目的取交集，禁止一条“总同意”覆盖全部用途。
2. **`scope` 必填**：写清字段范围（如 `person_pii;narrative`）与时间范围。
3. **`evidence_uri` 存签署原文快照**，`channel` 记 `web_form|offline|contract`；`publishing`、`third_party_share` 须额外取证（可展示版本 + 单独勾选）。
4. **撤回 ≠ 删除**，按 `consent_withdrawal_action`（§11）级联：

| 目的 | 撤回动作 | 必须删除 | 可保留为聚合 |
|---|---|---|---|
| `matching` | 停止推荐 | 未来 `match_result` 生成；`preference`、`person_constraint` 个体行 | 历史 `match_run` 的总体命中率（去 person_id） |
| `research_report` | 出库 | `derived_feature`、`match_result` 中该人个体行 | `v_skill_supply` 等只含计数与均值的行 |
| `product_improve` | 出库 | 日志中的个人标识与 `query fingerprint` 关联 | 功能使用计数 |
| `publishing` | 下架 | 已发布案例中的可识别元素 | 已匿名化的 `transition_case`（须先转 `person_id IS NULL`） |
| `third_party_share` | 追溯通知 + 停止 | 下游交付物清单；`access_log` 中该共享批次记录 | 无 |

级联实现（同一事务）：①置 `consent_record.revoked_at`；②若无其他有效同意，置 `person.status='withdrawn'`（001 已有该取值），RLS 随即拒绝该人所有行；③删 `person_pii` 行、`narrative` 及其 L0 文件；④聚合层保留数据但撤下 person_id；⑤全程写 `change_log`。**撤回 ≠ 抹除审计痕迹**：`access_log` 与 `change_log` 依法不随撤回删除。

## 4. 访问控制落地（RLS × access_policy）

### 4.1 判定模型

`access_policy` 是唯一判定源（002 已建，禁止代码里硬编码 tier）：`object_type='field'` 时 `object_id` 取 `field_catalog.field_id`（如 `F_PERSON_HEALTH_LIMITS`），`action` 取 `CT_ACTION` 五值；会话上下文 `mt.actor`/`mt.actor_tier`/`mt.scope` 由应用层每次连接设置。字段级策略种子见 §11(6)。

### 4.2 可执行 RLS 策略（以 T3 表为例）

```sql
-- 层级数值化（T0<T1<T2<T3<X），供策略比较
CREATE OR REPLACE FUNCTION mt.tier_rank(t TEXT) RETURNS INT
LANGUAGE sql IMMUTABLE AS $$
  SELECT CASE t
    WHEN 'T0' THEN 0 WHEN 'T1' THEN 1 WHEN 'T2' THEN 2
    WHEN 'T3' THEN 3 WHEN 'X' THEN 99 ELSE -1 END;
$$;

ALTER TABLE person_pii      ENABLE ROW LEVEL SECURITY;
ALTER TABLE person_pii      FORCE  ROW LEVEL SECURITY;
ALTER TABLE person_demographics ENABLE ROW LEVEL SECURITY;
ALTER TABLE person_constraint      ENABLE ROW LEVEL SECURITY;

-- 行级：只能命中本人（自助场景）或平台授权角色；且该人未被撤回
CREATE POLICY p_pii_row_owner ON person_pii
  FOR SELECT USING (
    EXISTS (SELECT 1 FROM person p
            WHERE p.person_id = person_pii.person_id
              AND p.status = 'active')
    AND ( person_pii.person_id = NULLIF(current_setting('mt.actor', true), '')  -- 本人查阅
          OR current_setting('mt.role', true) IN ('dpo','pii_operator')        -- 授权角色
        )
  );
CREATE POLICY p_pii_no_direct_export ON person_pii AS RESTRICTIVE
  FOR SELECT USING (current_setting('mt.scope', true) <> 'row_export');

-- 动作级：动作 × 图层两点判定（field 级策略表 002 已建，此处只加校验）
CREATE OR REPLACE FUNCTION mt.can_access(p_obj_type TEXT, p_obj_id TEXT, p_action TEXT)
RETURNS BOOLEAN LANGUAGE sql STABLE AS $$
  SELECT mt.tier_rank(current_setting('mt.actor_tier', true))
         >= mt.tier_rank(ap.min_tier)
  FROM access_policy ap
  WHERE ap.object_type = p_obj_type
    AND ap.object_id   = p_obj_id
    AND ap.action      = p_action;
$$;

-- 敏感字段读取：X 动作永不通过
CREATE POLICY p_pii_field_action ON person_pii AS RESTRICTIVE
  FOR SELECT USING (
    current_setting('mt.action', true) IS NULL
    OR mt.can_access('field','F_PERSON_PII_NAME', current_setting('mt.action', true))
  );

-- 派生字段列级：无 T3 权限时在读视图中置空（库内不落地明文）
CREATE VIEW v_person_demographics_masked AS
SELECT person_id, birth_year, sex, hukou_province, hukou_type,
       CASE WHEN mt.tier_rank(current_setting('mt.actor_tier', true)) >= 3
            THEN health_limits ELSE NULL END AS health_limits
FROM person_demographics;
```

### 4.3 T2“数据不落地”的实现

1. **物理隔离**：分析副本导出 Parquet 时只含 `subject_code`（`person_id` 经项目内 HMAC 置换）与 T0/T1 字段，物理删列而非打码；T2/T3 字段不进副本。
2. **只返回聚合**：T2 请求走 `marts` 接口，服务端强制 `HAVING COUNT(DISTINCT subject_code) >= 5`，返回体只含计数、分位数、均值；`SELECT *` 被 `p_pii_no_direct_export` 与列白名单拒绝。
3. **导出留痕**：所有 `export_aggregate`/`bulk_download` 必写 `access_log`（`action`、`row_count`、`purpose`、`detail.cells_suppressed`）。
4. **观测期前置**：任何“此人没有 X”的结论必须先过 `observation_window`（002 的 `v_gap_candidates` 强制），窗口外只能表述为“未记录”。

## 5. 聚合与披露控制

**结论：采用 k-匿名（k≥5）+ 小样本抑制，暂不引入差分隐私。** 本库披露面只有离线聚合交付物，没有交互式个体级查询，k≥5 加抑制已足够；DP 会把 17 族 × 学历 × 城市这类细粒度交叉压到噪声以下，而这正是价值所在。**升级条件**：一旦开放按需查询或个体级受控访问，再补 local DP 与查询预算。

细则：①出库单元格 `n < 5` 一律置 NULL，标注 `suppressed(n<5)`，禁出 0 或区间中值；②时间序列按滚动 3 个月聚合，防逐月相减还原；③交叉表禁同时给“合计”与全部子项；④阈值写入 `dataset_release.record_set_jsonld` 并随 `checksum_sha256` 冻结；⑤`v_skill_supply`、`v_skill_demand` 须 `HAVING COUNT(DISTINCT person_id) >= 5` 才进报告。

## 6. 数据生命周期

| 数据类 | 保留期 | 到期动作 |
|---|---|---|
| `person_pii` | 同意有效期内；撤回/注销后 ≤30 天 | 物理删除 + 密钥轮换 |
| `narrative` 与 L0 简历原文 | 账号有效期内；注销后 90 天 | 删除文件 + 抹 `raw_ref`，保留 `raw_sha256` 供审计 |
| `skill_assertion` / `education_record` / `evidence` | 同意有效期内 | 撤回即删个体行 |
| `match_run` / `match_result` | 24 个月 | 聚合后删除个体行（保留算法版本与总体指标） |
| `access_log` | 在线 24 个月 + 归档 12 个月（满足网安法 ≥6 个月） | 归档后删除 |
| L0 岗位原始 HTML | 36 个月 | 删正文保 `raw_sha256` + `provenance` |
| `dataset_release` / `change_log` / `code_table` | 永久 | 不删除（非个人信息） |

实现：`retention_policy` 与 `data_lifecycle_run` 由每月 1 日 02:00 定时任务按序执行 `delete|anonymize|archive`，逐类写运行记录与 `change_log`，`legal_hold=true` 跳过并标注。**禁止“只写策略不执行”**：连续两期 `data_lifecycle_run` 缺失即视为合规事件（触发 §8）。

个体权利请求统一登记 `subject_request`，SLA：**查阅与更正 ≤15 个工作日；删除与撤回 ≤15 个工作日（涉第三方共享加 15 日追溯通知）；解释（第 24 条）≤5 个工作日**。流程：受理 → 核验（证件号 HMAC 比对，不存明文）→ 按 `person.subject_code` 定位全库血缘 → 执行（写 `change_log`）→ 答复（`outcome`/`detail`，含不可删除项的法定依据）。超期未办结进月度合规看板。

## 7. 采集合规

**三段式来源准入规则**（`source_registry` 为唯一入口，未登记不得入库）：

1. **官方来源**：`source_type='official_doc'`、`evidence_grade='A'`，可作主结论。
2. **公开来源**：`source_type='web_scrape'` 必须登记 `license_note` 与 `robots_checked_at`，且该日期距今 ≤90 天，否则采集管道拒跑（对应 `docs/03` §7“0 违规”验收）；只允许静态页面，禁止绕过验证码/登录墙/反爬（智联、前程无忧、丁香人才仅人工抽样；BOSS 直聘、LinkedIn、Indeed 禁止自动化）。
3. **授权来源**：`source_type='partner_feed'|'survey'|'interview'` 必须凭 DUC 登记，`license_note` 写明授权范围与有效期；`evidence_grade` 按来源类型限定（B 须含样本量，C 禁止外推，D 禁止进对外主结论）。

**红线**：绝不采集求职者个人简历；人才侧数据只能来自本人授权或合作方合法授权。**来源下架**：按 `source_id` 置 `job_posting.quality_flags ||= '{excluded}'`、`valid_to=now()`，并置 `source_registry.status='retired'`、记 `downloaded_at`；001 禁止物理删除，故下架 = 标记 + 所有导出与 `marts` 过滤 `excluded` + 删 L0 原文文件，既停止使用又可审计。

## 8. 审计与事件响应

`access_log` 记录 `actor`、`actor_role`、`action`（`read|export|query|match_run`）、`target`、`access_tier`、`row_count`、`purpose`、`at`，以及 `detail` JSONB 中的 `session_id`、`query_fingerprint`、`cells_suppressed`、`result_status`——新增项优先入 `detail`，避免改表。纪律：①只追加，`REVOKE UPDATE, DELETE`；②每次 T3 读取必有一条，缺 `purpose` 的访问视为违规；③保留 24 个月在线 + 12 个月归档；④每月抽查 20 条导出记录，核对 DUC 与 purpose。

**数据泄露应急流程**（发现—遏制—评估—通知—复盘）：

| 阶段 | 动作 | 时限 | 留痕 |
|---|---|---|---|
| 发现 | 任何角色可上报 | 即时 | `incident_report` |
| 遏制 | 撤销会话 / 轮换 `encryption_key_id` / 下线接口 | ≤2 小时 | `change_log` |
| 评估 | 定级：涉及层（T0–T3）、字段、人数、是否含健康或证件号 | ≤24 小时 | `incident_report.severity` |
| 通知 | 监管：T3 或人数 ≥100 则 24 小时内报；个人：涉 T3 且可能影响权益及时告知 | ≤72 小时 | 通知原文归档 |
| 复盘 | 根因、影响、纠正措施、检查项增补 | ≤30 天 | `postmortem` + §10 增项 |

## 9. 组织与制度

| 文档 / 制度 | 内容要点 | 责任角色（非人名） |
|---|---|---|
| 隐私政策 | 逐项 `purpose`、字段清单、共享、期限、主体权利入口 | DPO 起草，法务复核 |
| 数据处理协议（DPA） | 处理者/共同控制者界定、安全义务、审计权 | 法务 + 数据治理负责人 |
| 数据使用协议（DUC） | 与 `dataset_release` 一一对应，写明允许用途、禁止再识别、违约后果 | 数据发布审批人 |
| release note + 数据字典 | `doc_codebook_uri` 必填（未填不得发布） | 数据管理员 |
| 采集合规台账 | `source_registry` 导出，含 `robots_checked_at` 与许可结论 | 采集负责人 |
| 事件响应手册 / 保留期表 | §6、§8 的作业化版本 | 安全工程师 + DPO |
| schema 变更记录 | 任何字段、词表、策略变更均入 `change_log` | 数据管理员 |

**职权分离**：提出发布者不得批准发布（双人复核）；DPO 对任何发布有否决权且不向业务负责人汇报；T3 读取需 DPO 书面授权并在 `access_policy` 留痕。

## 10. 发布前合规检查清单

1. 本次交付涉及的表与字段已逐条登记在 `field_catalog` / `attribute_definition`。
2. `source_registry` 中每个活跃来源均有 `license_note`；`web_scrape` 型 `robots_checked_at` ≤90 天。
3. 采集批次中无求职者个人简历来源；人才侧数据均可指向本人授权或 DUC。
4. 每条 `consent_record` 的 `purpose` 在五枚举内，`scope` 非空，`granted_at` 早于数据写入。
5. T3 字段（`health_limits`、`person_pii.*`）有独立同意记录与 `view_inline/export_row` 策略行。
6. `access_policy` 覆盖本次交付涉及的全部 (object, action) 组合，无缺行。
7. `person_pii`、`person_demographics`、`person_constraint` 已 `ENABLE` 且 `FORCE ROW LEVEL SECURITY`。
8. 交付脚本无硬编码 tier 判断，全部经 `mt.can_access()` 或策略表。
9. T2 交付物为聚合结果，未包含 `person_id` 或原文引用。
10. 所有对外单元格 `n ≥ 5`；被抑制单元格标注 `suppressed(n<5)` 且未输出 0。
11. 交叉表未同时输出合计与全部子项（无互补披露）。
12. 任何“未具备/缺口”结论均有 `observation_window` 覆盖证明，或已改写为“未记录”。
13. 阈值与抑制规则已写入 `dataset_release.record_set_jsonld` 与 release note。
14. `dataset_release.doc_codebook_uri` 非空，`status` 已走完 review → published。
15. `checksum_sha256` 已计算并写 `change_log`。
16. 本次导出在 `access_log` 有对应记录，含 `purpose`、`row_count`、`session_id`。
17. `retention_policy` 覆盖本次新增的每一类数据；最近一期 `data_lifecycle_run` 无遗漏且执行成功。
18. 无待办 `subject_request` 超期。
19. 自动化决策交付物含 `explanation` 与人工复核入口（`refuse`）。
20. 涉跨境的数据流为 0，或有单独同意 + 单独影响评估 + DPO 签字。

### 11.1 新增对象（DDL 落在 `schema/sql/003_gov_compliance.sql`）
