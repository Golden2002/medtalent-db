# 05 · 匹配与分析引擎方案（Match & Analytics Engine）

> 上游：`01-数据模型设计.md`（表主干）、`03-岗位图谱构建方案.md`（岗位侧）、`research/04-技术架构-可扩展人才数据模型与匹配引擎.md`（选型结论）。
> 本文回答三件事：**怎么打分、怎么解释、怎么分析**。表名字段名一律以 `schema/sql/001_core_schema.sql`、`002_ukb_patterns.sql` 为准。

**三条硬纪律（违反即不予上线）**
1. 任何"此人没有 X"的结论，必须先证明 X 落在该人的 `observation_window` 内；否则只能写"未记录"（`01` §9 新增纪律）。
2. 任何 `match_result` 必须带 `explanation` 与 `score_breakdown`；无解释的结果不得展示（PIPL 第 24 条"说明 + 拒绝"）。
3. 任何分数都是派生特征：`match_run.algo_version` + `match_run.params` 必须能复现同一次运行；算法改版不改数据。

## 1. 三段式流水线

```
① 硬过滤（SQL，收窄池子）      ② 混合召回（BM25 + pgvector → RRF）   ③ 重排（特征 + 可解释）
person×education×credential  →  search_document(tsvector) ─┐
×preference×job_requirement     embedding(HNSW, cosine)  ─┴→ RRF → 打分 → match_result/gap_analysis
```

### 1.1 检索层补丁（唯一新增 DDL，建议落 `schema/sql/003_retrieval.sql`）

001/002 未定义向量与全文表，这是差额补齐；ID 前缀新增 `doc_`/`emb_`，须先登记 `entity_catalog` 与 `field_catalog`：

```sql
CREATE TABLE search_document (
  doc_id TEXT PRIMARY KEY,                    -- doc_<ULID>
  owner_type TEXT NOT NULL CHECK (owner_type IN ('person','job_posting')),
  owner_id TEXT NOT NULL,
  doc_kind TEXT NOT NULL,                     -- resume_text | jd_text
  content_tsv TSVECTOR, segment_uri TEXT,     -- 指向 L0 原文，保证可回溯
  content_hash TEXT NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (owner_type, owner_id, doc_kind));
CREATE INDEX idx_search_doc_tsv ON search_document USING gin (content_tsv);

CREATE TABLE embedding (
  embedding_id TEXT PRIMARY KEY, owner_type TEXT NOT NULL, owner_id TEXT NOT NULL,
  model TEXT NOT NULL, dim SMALLINT NOT NULL, vec VECTOR(1024) NOT NULL,
  content_hash TEXT NOT NULL,                 -- 内容未变则不重算（同 derived_feature.inputs_hash）
  algo_version TEXT NOT NULL, computed_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (owner_type, owner_id, model));
CREATE INDEX idx_embedding_hnsw ON embedding USING hnsw (vec vector_cosine_ops) WHERE model = 'bge-m3';
```

JD 侧查询文本由 `job_posting.title_raw` + `job_task.task_text` + `job_requirement.raw_text` 拼接——**只用原文，不用归一化结果**，这样任一分数都能回到 L0 原文。

调用契约：一次匹配 = 一条 `match_run`（记 `algo_version`、`params` 快照、`person_count`、`job_count`）+ N 条 `match_result`。目标侧两种形态共用本文公式，差别只在权重来源——`occupation` 走能力画像，`w_c` 取自 `job_competency_weight`；`job_posting` 走真实 JD，`w_c` 取自 `job_requirement.essentiality`。同一人同一岗可被多次运行打分，历史行永不覆盖（append-only）。

### 1.2 ① SQL 硬过滤（学历/专业/执照/城市/应届）

```sql
-- mt.degree_rank(t) := (SELECT cv.sort_order FROM code_value cv
--   WHERE cv.code_table_id='CT_DEGREE_LEVEL' AND cv.code=t)
CREATE OR REPLACE FUNCTION mt.degree_rank(p_level TEXT) RETURNS INT AS
$$ SELECT COALESCE((SELECT cv.sort_order FROM code_value cv
     WHERE cv.code_table_id='CT_DEGREE_LEVEL' AND cv.code=p_level), 0) $$ LANGUAGE sql STABLE;

WITH tgt AS (
  SELECT job_id, job_family, city, education_req, major_req, license_req, is_campus
  FROM job_posting WHERE job_id = $1 AND verify_status <> 'disputed'),
pool AS (
  SELECT pe.person_id
  FROM person pe, tgt
  WHERE pe.status = 'active'
    -- 学历
    AND (tgt.education_req IS NULL OR EXISTS (
          SELECT 1 FROM education_record e
          WHERE e.person_id = pe.person_id AND COALESCE(e.is_graduated,true)
            AND mt.degree_rank(e.degree_level) >= mt.degree_rank(tgt.education_req)))
    -- 专业（临床/目录码，保留 major_raw 兜底）
    AND (tgt.major_req IS NULL OR EXISTS (
          SELECT 1 FROM education_record e
          WHERE e.person_id = pe.person_id
            AND (e.is_clinical IS TRUE OR e.major_raw ILIKE '%'||tgt.major_req||'%')))
    -- 执照：license_req 中每一项都必须有有效 credential
    AND NOT EXISTS (
          SELECT 1 FROM unnest(tgt.license_req) lic
          WHERE NOT EXISTS (SELECT 1 FROM credential c
                            WHERE c.person_id = pe.person_id AND c.status = '有效'
                              AND c.credential_type = lic))
    -- 城市：硬性偏好外的城市不召回
    AND NOT EXISTS (
          SELECT 1 FROM preference pf
          WHERE pf.person_id = pe.person_id AND pf.pref_type = 'city'
            AND pf.is_hard IS TRUE AND COALESCE(pf.value_code,'') <> tgt.city)
    -- 应届
    AND (tgt.is_campus IS NOT TRUE OR COALESCE((
          SELECT MAX(e.end_date) FROM education_record e WHERE e.person_id = pe.person_id),
          DATE '1900-01-01') >= CURRENT_DATE - INTERVAL '2 years')
    -- 通用硬性要求条目（education|major|license|experience|language|other）
    AND NOT EXISTS (
          SELECT 1 FROM job_requirement jr
          WHERE jr.job_id = tgt.job_id AND jr.requirement_kind = 'hard'
            AND NOT mt.person_satisfies(pe.person_id, jr.requirement_id)))
SELECT person_id FROM pool;
```

`mt.person_satisfies(person_id, requirement_id)` 按 `job_requirement.requirement_type` 分派：`license`→`credential.status='有效'`；`skill/knowledge`→`skill_assertion.level >= min_level`，不足时回退 `substitutable_by` 与 `concept_relation(relation_type IN ('substitute_of','prerequisite_of'))`；`experience`→`employment_record`/`training_record.months` 求和。**返回三态** `satisfied / substitutable / unmet`，`unmet` 进否决，`substitutable` 进解释的"替代路径"。

### 1.3 ② 混合召回 + RRF 融合

RRF 不需要两路分数量纲对齐（Cormack 2009），`k=60`：

```sql
WITH pool AS (SELECT person_id FROM mt.hard_filter_pool($1)),   -- §1.2
q AS (SELECT mt.job_query_text($1) AS txt, mt.job_query_vec($1) AS qv),
kw AS (
  SELECT d.owner_id AS person_id,
         row_number() OVER (ORDER BY ts_rank_cd(d.content_tsv, plainto_tsquery('simple', q.txt)) DESC) AS rnk
  FROM search_document d, q
  WHERE d.owner_type='person' AND d.owner_id IN (SELECT person_id FROM pool)
  LIMIT 500),
vec AS (
  SELECT em.owner_id AS person_id,
         row_number() OVER (ORDER BY em.vec <=> q.qv) AS rnk
  FROM embedding em, q
  WHERE em.owner_type='person' AND em.model='bge-m3'
    AND em.owner_id IN (SELECT person_id FROM pool)
  ORDER BY em.vec <=> q.qv LIMIT 500)
SELECT COALESCE(kw.person_id, vec.person_id) AS person_id,
       COALESCE(1.0/(60+kw.rnk),0) + COALESCE(1.0/(60+vec.rnk),0) AS rrf_score
FROM kw FULL OUTER JOIN vec USING (person_id)
ORDER BY rrf_score DESC LIMIT 200;
```

### 1.4 ③ 重排：特征装配

重排不改召回集合，只把候选按 §2 公式打分并把每个 `concept` 的贡献写进 `match_result.score_breakdown`（`matched_concepts` / `gap_concepts` 同步落 TEXT[]）。

## 2. 评分公式

对目标 t（`occupation` 或 `job_posting`）与个人 p，权重取 `job_competency_weight.importance`（无画像时回退 `job_requirement.essentiality`，再缺省 0.5）：`w_c`、要求等级 `L_t(c)=level_required`。

**有效等级**（把"等级 × 依据 × 置信度 × 层级折损"合并成一个数）：

```
φ(p,c) = min(5, max over a∈skill_assertion  [ level_a × confidence_a × κ(basis_a) × 0.8^depth ])
κ: certificate|output|clinical_volume|supervisor = 1.0, assessment = 0.9, self_report = 0.7, 其他 = 0.6
depth 由 concept_ancestor 得到（下级能力顶替上级，每层折损 0.8）
命中判据 hit(p,c) := φ(p,c) ≥ 0.5；无 evidence_id 时 confidence ≤ 0.5（001 的 CHECK 已强制）
```

- **能力覆盖度**：`COV = Σ_{hit} w_c / Σ_c w_c`
- **等级达标度**：`LVL = Σ_{hit} w_c·min(1, φ(p,c)/max(L_t(c),1)) / Σ_{hit} w_c`
- **可迁移性加权**：`TRANS = Σ_{hit} w_c·(transferability/5) / Σ_{hit} w_c`（`transferability` 为空按 2.5 计）
- **偏好契合**：`PREF = Σ preference.weight·match(pref_type, t) / Σ preference.weight`
- **缺口惩罚**（只计**真缺口**，见 §4）：`GAPPEN = Σ_{c∈gap ∧ essential} w_c / Σ_{c∈essential} w_c`
- **硬性否决**：`HARD = 0 若任一 hard 要求 unmet，否则 1`

```
Score(p,t) = HARD × (0.45·COV + 0.25·LVL + 0.15·TRANS + 0.15·PREF) × (1 − 0.6·GAPPEN) × 100
```

权重取"覆盖面优先、等级次之"，因为覆盖度最能被证据支撑；`GAPPEN` 只惩罚 essential 项，避免与 `COV` 对同一缺口双重扣分。硬性不满足者**不丢出结果**，而是 `score_total=0` + `explanation` 写明"未满足硬性要求：执业医师资格"，否则用户看不到依据、无法申诉。

## 4. 观测期前置校验（缺口判定）

```sql
-- 缺口三态：satisfied / gap（窗口内确无记录）/ not_observed（窗口不覆盖，不出缺口）
WITH req AS (SELECT concept_id, importance, level_required, essentiality
             FROM job_competency_weight WHERE occupation_id = $1),
cov AS (SELECT window_id, start_date, end_date FROM observation_window
        WHERE person_id = $2 AND window_type IN ('resume_coverage','employment_span','platform_active')
          AND start_date <= CURRENT_DATE
          AND (end_date IS NULL OR end_date >= CURRENT_DATE - INTERVAL '18 months'))
SELECT r.concept_id,
       CASE WHEN EXISTS (SELECT 1 FROM skill_assertion sa
                         WHERE sa.person_id=$2 AND sa.concept_id=r.concept_id AND sa.level >= 1)
              THEN 'satisfied'
            WHEN EXISTS (SELECT 1 FROM cov) THEN 'gap'
            ELSE 'not_observed' END AS state,
       (SELECT window_id FROM cov ORDER BY end_date DESC NULLS FIRST LIMIT 1) AS window_ref
FROM req r;
```

粗筛可先用 002 已建的 `v_gap_candidates` 取"窗口内无记录"的候选，再按上面三态逐项确认（该视图只解决"有没有记录"，不解决"该不该算缺口"）。

`gap_analysis` 只在 `state='gap'` 时写入；所用窗口记入 `match_result.score_breakdown.window_ref`，并把覆盖率冻结为 `derived_feature(feature_name='observation_coverage_at_gap', inputs_hash=...)`，保证事后可复核。

**反例（回归测试用例）**：某硕士简历只覆盖 2016-09～2021-06（在校），岗位要求"1 年以上临床研究经验"。若跳过窗口校验，引擎会输出"缺：临床研究经验 → 建议补实习"，把**简历没写**当成**不具备**；正确输出是 `not_observed`，话术为"未记录，建议补充 2021 年后的经历后再评估"。第二个反例：`credential.status='备考中'` 的 GCP 证应记为 `substitutable` 而非缺口。

## 5. 分析层（marts）设计

**星型模型**（`01` §7.1 清单 + 新增 `fact_match`）：
- 维度：`dim_person`、`dim_occupation`、`dim_employer`、`dim_concept`、`dim_geo`、`dim_time`、`dim_education`
- 事实：`fact_skill_demand`（岗位需求侧频次×重要性）、`fact_capability_supply`（供给侧能力分布）、`fact_posting`、`fact_salary`、`fact_transition`、`fact_match`

**DuckDB + Parquet 离线路径**：规范层按实体导出 Parquet（按 `valid_from` 年份分区），DuckDB 直接读，不复制业务逻辑：

```bash
python -m mt.export --tables job_posting,job_requirement,skill_assertion,education_record \
  --out marts/raw/ --partition-by year    # 只导出 access_tier <= T1 的列
duckdb -c "CREATE VIEW fact_posting AS SELECT * FROM read_parquet('marts/raw/fact_posting/*.parquet');"
```

**指标即代码**：`metric_definition.definition_sql` 存可执行 SELECT，`make marts` 扫描 `status='active'` 的指标并执行，结果写 Parquet + `change_log`。指标 SQL 必须只含 SELECT 且不依赖 PG 特有语法，以便 dbt-postgres / DuckDB 双跑。

**三个客户会问的问题**

Q1 医学硕士转行药企的常见路径与薪酬分位（直查 L1）：

```sql
WITH ms AS (SELECT DISTINCT person_id FROM education_record
            WHERE degree_level = '硕士' AND (is_clinical IS TRUE OR major_code LIKE '10%')),
flow AS (SELECT tc.to_occupation, unnest(tc.bridge_concepts) AS bridge, tc.years_taken
         FROM transition_case tc JOIN ms USING (person_id)
         WHERE tc.to_industry IN ('药企','CRO','医疗器械','医药咨询')),
bridge AS (SELECT to_occupation, bridge, COUNT(*) AS n,
                  ROUND(AVG(years_taken),1) AS avg_years
           FROM flow GROUP BY 1,2)
SELECT b.to_occupation, b.bridge, b.n, b.avg_years,
       sb.city, sb.p25, sb.p50, sb.p90, sb.sample_size, sr.evidence_grade, sb.as_of
FROM bridge b
JOIN salary_benchmark sb ON sb.occupation_id = b.to_occupation AND sb.degree_level = '硕士'
JOIN source_registry sr ON sr.source_id = sb.source_id
WHERE b.n >= 3 AND sb.as_of >= CURRENT_DATE - INTERVAL '24 months'
  AND sr.evidence_grade IN ('A','B')          -- C/D 级不得进对外主结论
ORDER BY b.to_occupation, b.n DESC;
```

Q2 哪类能力最稀缺（供给侧缺口 Top-N，走 marts）：

```sql
SELECT d.concept_id, c.preferred_label, d.posting_count AS demand, s.person_count AS supply,
       ROUND(d.demand_score - s.supply_score, 3) AS scarcity
FROM fact_skill_demand d
LEFT JOIN fact_capability_supply s USING (concept_id)
JOIN dim_concept c USING (concept_id)
WHERE d.posting_count >= 30
ORDER BY scarcity DESC LIMIT 20;
```

Q3 转行机会矩阵（医学依赖度低 × 薪酬高 × 可迁移，走 marts/`occupation`）：

```sql
SELECT o.family, o.medical_reliance, o.transferability,
       COUNT(DISTINCT sb.benchmark_id) AS anchors,
       ROUND(percentile_cont(0.5) WITHIN GROUP (ORDER BY sb.p50), 0) AS p50_median
FROM occupation o
JOIN salary_benchmark sb ON sb.occupation_id = o.occupation_id
WHERE sb.degree_level = '硕士' AND sb.as_of >= CURRENT_DATE - INTERVAL '2 years'
GROUP BY 1,2,3 HAVING COUNT(DISTINCT sb.benchmark_id) >= 3
ORDER BY o.medical_reliance ASC, p50_median DESC;
```

## 6. 面向客户的四个输出物

| 输出物 | 数据来源表 | 生成方式 |
|---|---|---|
| **岗位地图** | `occupation`(medical_reliance, transferability, entry_paths) + `job_competency_weight` + `fact_posting` | 17 族二维矩阵（依赖度 × 可迁移度）；`fact_posting` 提供每格在招量 |
| **能力缺口报告** | `gap_analysis` + `observation_window` + `job_competency_weight` + `concept` | 按缺口权重×补齐成本排序，每行附 `remedy_type` 与窗口；`not_observed` 单列"待补充信息" |
| **转行路径建议** | `transition_case` + `concept_relation` + `concept_ancestor` + `gap_analysis` | 沿 `bridge_concepts` 取真实案例，2-hop 内生成"桥梁能力 → 目标岗"路径，标 `years_taken` 与案例数 |
| **薪酬锚点** | `salary_benchmark` + `job_posting.salary_min/max` + `source_registry.evidence_grade` | 岗位族×城市×学历分位数，必带 `sample_size`、`as_of`、`evidence_grade`；`job_posting` 仅作 C 级举例 |

四者都是 marts 的物化视图 + 模板渲染，**不接事务层直查**（`01` G5）。

调度：Parquet 导出与 marts 刷新每日一次；`metric_definition` 每次改动必须升 `version` 并写 `change_log`，因为客户报告里出现的每个数字都要能回答"用哪版口径算的"。

## 7. 验证方案

1. **人工标注集**：抽 300–500 对 `(person, target)`，按"可直接投 / 需补齐 / 不可投"三档双人标注，Cohen's kappa ≥ 0.6；覆盖 17 族、四个地域层级，避免只在临床族验证。
2. **排序指标**：`P@10 ≥ 0.60`、`NDCG@10 ≥ 0.70`、`Recall@50 ≥ 0.85`；**硬性违规率必须为 0**（不满足硬性条件者不得进 Top-10），这是否决即"可拒绝"之外的底线。
3. **可解释性抽检**：每批随机抽 5%（≥20 条）人工核对——每条命中必须能回指 `evidence_id` 或 `search_document.segment_uri` 原文，每条缺口必须带 `window_ref`；不可解释率 > 0 视为发布阻断。
4. **反例回归**：把 §4 两个反例固化为测试用例（缺窗口、备考中证书），引擎输出 `gap` 即测试失败。
5. **冷启动**：新人无行为数据 → 纯内容匹配（`skill_assertion` + 硬条件），并在结果中标注"依据仅来自档案"；新岗位无历史 → 用同 `job_family` 的 `job_competency_weight` 画像做先验；两边都冷 → 用 `concept_ancestor` 上位概念粗召回，宁可召回多、排序弱，并标 `coverage_gap` 不对外给分位数结论。

## 8. 分期

| 期 | 算法（`match_run.algo_version`） | 判定标准（可验收） | 明确不做 |
|---|---|---|---|
| **MVP（规则版）** | `rule_v0.1`：①SQL 硬过滤 + `tsvector`/`pg_trgm` 单路召回 + §2 固定权重打分 | Top-10 命中率 ≥0.45；可解释率 100%；缺口 100% 过窗口校验；单次运行 ≤10 万人 | 向量召回、RRF、LTR、图算法、独立向量库 |
