# 07 · 数据字典与扩展机制 · 操作手册

> 遇到新需求该动哪里。结构以 `001_core_schema.sql`/`002_ukb_patterns.sql` 为准，机制判据见 `01-数据模型设计.md` §5–§6。SQL 默认已 `SET search_path TO mt, public;`。
> **只有三条机制：A 代码表 / B 属性登记 / C 断言。禁止第四种（随手 ALTER TABLE）。**

## A · 新增枚举值（如新岗位族）
**判据**：是某个已有维度的取值，不动表结构。
**操作**：插 `code_value`（`parent_code` 须同表内已存在）；被取代的旧值**只废弃不删除**。若是全新维度，先登记代码表本身：
```sql
INSERT INTO code_table (code_table_id,name,description,hierarchical,external_standard,version)
VALUES ('CT_JOB_FAMILY_V2','岗位族（2026 修订）','F01–F17 重划版',true,'自定义','1.0.0');
```
```sql
INSERT INTO code_value (code_table_id,code,label_zh,label_en,parent_code,level,sort_order,
  definition,aliases,external_mapping,effective_from)
VALUES ('CT_JOB_FAMILY','F18','健康险科技与健康管理','Insurance Tech & Health Management',
  NULL,1,180,'健康险科技、TPA、慢病管理；区别于 F06 的偏产品技术侧',
  ARRAY['健管科技','TPA'],'{"ISCO-08":"3253"}'::jsonb, DATE '2026-01-01');

UPDATE code_value SET deprecated=true, replaced_by='F18', effective_to=DATE '2025-12-31'
WHERE code_table_id='CT_JOB_FAMILY' AND code='F06';
```
**验证**：`SELECT code,deprecated,replaced_by FROM code_value WHERE code_table_id='CT_JOB_FAMILY' AND code IN ('F06','F18');` —— F18 未废弃、F06 `replaced_by='F18'`；再确认无业务数据仍挂 F06：`SELECT count(*) FROM job_posting WHERE job_family='F06';` 应为 0。CSV 同步追加到 `code_table_seed.csv` 并跑质检门。
**反例**：在 `job_posting.job_family` 裸写中文；`DELETE` 旧值（历史 JD 变孤儿）；改 `CHECK` 约束加枚举。

## B · 新增字段（如"是否独生子女"）
**判据**：要反复过滤/排序/约束/外键 → 正式列；只是要记得住 → 机制 B（零 DDL）。
**写法一（推荐）**：
```sql
INSERT INTO attribute_definition (attr_key,entity_id,title,data_type,value_range,indexed,status,version)
VALUES ('PERSON_ONLY_CHILD','person','是否独生子女','boolean','{true,false}',false,'active','1.0.0');

INSERT INTO field_catalog (field_id,entity_id,title,description,data_type,cardinality,
  collection_method,access_tier,status,version,owner)
VALUES ('F_PERSON_ONLY_CHILD','person','是否独生子女','用于家庭资源与流动意愿分析','boolean',
  'scalar','questionnaire','T2','active','1.0.0','research');

INSERT INTO field_value (value_id,field_id,subject_type,subject_id,instance_key,array_index,
  value_json,source_id,confidence,verify_status)
VALUES ('fv_01H8ZONLY0000000000001','F_PERSON_ONLY_CHILD','person','per_01H8Z0000000000000000001',
  '0',0,'{"value":true}'::jsonb,'src_self_report',0.7,'parsed')
ON CONFLICT (field_id,subject_type,subject_id,instance_key,array_index)
DO UPDATE SET value_json=EXCLUDED.value_json, confidence=EXCLUDED.confidence, recorded_at=now();
```
数值/日期/单选/多选分别用 `value_num`/`value_date`/`value_code`/`value_codes`；六列同时最多填两列（`chk_field_value_typed`）。
**写法二（升格为正式列）**：`ALTER TABLE person ADD COLUMN is_only_child BOOLEAN;` + 同一事务补 `field_catalog` 行 + `change_log`（`change_type='add'`，`from/to_version`）。
**验证**：`SELECT attr_key,status FROM attribute_definition WHERE attr_key='PERSON_ONLY_CHILD';`；值落位 `SELECT value_json,confidence FROM field_value WHERE field_id='F_PERSON_ONLY_CHILD';`；未登记键的巡检（期望 0 行）：
```sql
SELECT p.person_id, k FROM person p, jsonb_object_keys(p.attrs) k
LEFT JOIN attribute_definition ad ON ad.attr_key=k AND ad.entity_id='person' WHERE ad.attr_key IS NULL;
```
目录覆盖率巡检（每个字段目录项都应有对应的库内落地）：
```sql
SELECT entity_id, count(*) AS declared FROM field_catalog WHERE status='active' GROUP BY entity_id ORDER BY 2 DESC;
```
**反例**：直接往 `person.attrs` 塞未登记键；布尔值同时填 `value_text` 与 `value_num`（违反 1–2 列约束）；`field_value.field_id` 未登记（外键直接失败）。

## C · 新增实体（如"导师"）
**判据**：有独立 ID 与生命周期、≥3 个自有字段、被多表引用。仅一个属性走 B；探索期关系走 C（`assertion`，`predicate='supervised_by'`，`status='provisional'`）。`id_prefix` 取 ID 前缀表中未占用的三字母（001 §6.1 已占 `per/edu/trn/cre/emp/res/prj/awd/skl/evd/asm/job/occ/ems/con/fld/ct/src/run/mat/gap/trc`，本实体取 `men`，新增实体前先在 `entity_catalog` 查重）。
```sql
BEGIN;
INSERT INTO entity_catalog (entity_id,table_name,domain,description,id_prefix,schema_version,access_tier,status)
VALUES ('mentor','mentor','semantic','导师实体：师承网络与研究资源分析','men','1.0.0','T2','active');

CREATE TABLE mentor (
  mentor_id TEXT PRIMARY KEY, schema_version TEXT NOT NULL DEFAULT '1.0.0',
  name TEXT NOT NULL, institution TEXT, department TEXT, academic_title TEXT,
  is_doctoral_supervisor BOOLEAN DEFAULT false, research_areas TEXT[], h_index INTEGER,
  status TEXT NOT NULL DEFAULT 'active', valid_from DATE, valid_to DATE,
  recorded_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  source_id TEXT REFERENCES source_registry(source_id), confidence mt.confidence_t NOT NULL DEFAULT 0.8,
  verify_status mt.verify_status_t NOT NULL DEFAULT 'parsed',
  quality_flags TEXT[] NOT NULL DEFAULT '{}', attrs JSONB NOT NULL DEFAULT '{}'::jsonb);
CREATE INDEX idx_mentor_inst ON mentor(institution, department);

INSERT INTO field_catalog (field_id,entity_id,title,data_type,cardinality,collection_method,access_tier,status,version,owner) VALUES
 ('F_MENTOR_NAME','mentor','导师姓名','string','scalar','manual','T2','active','1.0.0','research'),
 ('F_MENTOR_INSTITUTION','mentor','所属机构','string','scalar','manual','T2','active','1.0.0','research'),
 ('F_MENTOR_RESEARCH_AREAS','mentor','研究方向','array','array','manual','T2','active','1.0.0','research');

INSERT INTO change_log (actor,object_type,object_name,change_type,from_version,to_version,detail)
VALUES ('data','entity','mentor','add','0.0.0','1.0.0','{"table":"mt.mentor","id_prefix":"men","fields":3}'::jsonb);
COMMIT;
```
**验证**：`SELECT entity_id,id_prefix,(SELECT count(*) FROM field_catalog f WHERE f.entity_id='mentor') FROM entity_catalog WHERE entity_id='mentor';`；表结构 `SELECT column_name,is_nullable FROM information_schema.columns WHERE table_schema='mt' AND table_name='mentor' ORDER BY ordinal_position;`；公共字段齐备应为 4：
```sql
SELECT column_name FROM information_schema.columns
WHERE table_schema='mt' AND table_name='mentor'
  AND column_name IN ('schema_version','verify_status','source_id','confidence');  -- 期望 4 行
```
再把 `entity_catalog` 与字段行追加进 seed CSV（`code_table_seed.csv` 不含实体，实体行在 `field_catalog_seed.csv` 中以 `entity_id` 出现），跑质检门确认引用存在。
**反例**：只建表不登记（字段目录外键写不进去）；复用已有前缀 `per_`；漏 `verify_status`/`confidence`（无法按证据分级过滤）。

## D · 扩展字段 promote 为正式列
**触发**：`attribute_definition.indexed=true`，或该字段进入匹配/报告主路径。三阶段**必须逐段上线**：expand 完成后老写入路径仍可用，backfill 可重跑，contract 才切换写入侧，任一段可停。
```sql
-- ① expand：只加列，不停服
BEGIN;
ALTER TABLE person ADD COLUMN IF NOT EXISTS is_only_child BOOLEAN;
INSERT INTO field_catalog (field_id,entity_id,title,data_type,cardinality,collection_method,access_tier,status,version,owner)
VALUES ('F_PERSON_IS_ONLY_CHILD','person','是否独生子女','boolean','scalar','questionnaire','T2','active','1.1.0','research')
ON CONFLICT (field_id) DO UPDATE SET version=EXCLUDED.version, updated_at=now();
INSERT INTO change_log (actor,object_type,object_name,change_type,from_version,to_version,detail)
VALUES ('data','field','person.is_only_child','add','1.0.0','1.1.0','{"phase":"expand"}'::jsonb);
COMMIT;   -- 回滚：ALTER TABLE person DROP COLUMN is_only_child;

-- ② backfill：幂等，只填 NULL
UPDATE person p SET is_only_child=COALESCE((fv.value_json->>'value')::boolean, fv.value_num::boolean),
       schema_version='1.1.0'
FROM field_value fv
WHERE fv.field_id='F_PERSON_ONLY_CHILD' AND fv.subject_type='person' AND fv.subject_id=p.person_id
  AND fv.instance_key='0' AND fv.array_index=0 AND p.is_only_child IS NULL;
-- 回滚：UPDATE person SET is_only_child=NULL WHERE schema_version='1.1.0';

-- ③ contract：封存属性入口，保留历史值
UPDATE attribute_definition SET status='promoted', promoted_to_field='F_PERSON_IS_ONLY_CHILD', version='1.1.0'
WHERE attr_key='PERSON_ONLY_CHILD';
INSERT INTO change_log (actor,object_type,object_name,change_type,from_version,to_version,detail)
VALUES ('data','field','person.is_only_child','promote','1.0.0','1.1.0',
        '{"from":"attribute_definition.PERSON_ONLY_CHILD"}'::jsonb);
```
**验证**：`SELECT ad.status, ad.promoted_to_field FROM attribute_definition ad WHERE ad.attr_key='PERSON_ONLY_CHILD';`（应为 `promoted`）；回填缺口 `SELECT count(*) FROM field_value fv JOIN person p ON p.person_id=fv.subject_id WHERE fv.field_id='F_PERSON_ONLY_CHILD' AND p.is_only_child IS NULL;` 应为 0。
**反例**：一步 `ADD COLUMN NOT NULL DEFAULT false`（把"未采集"伪造成"非独生"）；backfill 不幂等（覆盖人工修正）；contract 阶段删 `field_value` 行（破坏 append-only）。

## E · 新增派生指标
**判据**：人级一值 → `derived_feature`；一方一值 → `metric_definition`。两者都必记算法版本。
```sql
INSERT INTO field_catalog (field_id,entity_id,title,data_type,cardinality,collection_method,
  related_fields,derivation,strata,access_tier,status,version,owner)
VALUES ('F_PERSON_TRANSITION_FIT','person','转行适配度','number','scalar','derived',
  ARRAY['F_SKL_TRANSFERABILITY','F_SKL_CONFIDENCE','F_SKL_LEVEL'],
  '输入=skill_assertion 的 transferability/confidence/level 与 job_competency_weight；算法见 code/features/transition_fit_v1.py',
  'derived','T1','active','1.0.0','research');

INSERT INTO derived_feature (feature_id,subject_type,subject_id,feature_name,value_numeric,
  algo_version,inputs_hash,computed_at)
VALUES ('drv_01H8ZFEAT000000000001','person','per_01H8Z0000000000000000001','transition_fit',
  0.7342,'v1.2.0','sha256:9f2c...c41d',now())
ON CONFLICT (subject_type,subject_id,feature_name,algo_version)
DO UPDATE SET value_numeric=EXCLUDED.value_numeric, inputs_hash=EXCLUDED.inputs_hash, computed_at=now();

INSERT INTO metric_definition (metric_id,name,description,definition_sql,grain,version,owner,status)
VALUES ('met_job_family_demand','岗位族需求热度','近90天在招岗位数与要求强度',
 'SELECT jp.job_family, COUNT(DISTINCT jp.job_id) AS posting_cnt, AVG(jr.essentiality) AS avg_ess
    FROM job_posting jp LEFT JOIN job_requirement jr ON jr.job_id=jp.job_id
   WHERE jp.published_at >= CURRENT_DATE - INTERVAL ''90 days'' GROUP BY jp.job_family',
 'job_family','1.0.0','research','active');

INSERT INTO change_log (actor,object_type,object_name,change_type,from_version,to_version,detail)
VALUES ('research','metric','transition_fit','add','0.0.0','1.2.0',
 '{"algo_version":"v1.2.0","inputs_hash":"sha256:9f2c...c41d"}'::jsonb);
```
**验证/版本对比**：同 `algo_version` 重算走 UPSERT 覆盖，换算法换 `algo_version` 并存：
```sql
SELECT subject_id,
  MAX(value_numeric) FILTER (WHERE algo_version='v1.1.0') AS v1_1_0,
  MAX(value_numeric) FILTER (WHERE algo_version='v1.2.0') AS v1_2_0
FROM derived_feature WHERE feature_name='transition_fit' GROUP BY subject_id;
SELECT subject_id,feature_name,algo_version,count(*) FROM derived_feature GROUP BY 1,2,3 HAVING count(*)>1;
```
**反例**：把派生值 UPDATE 回 `skill_assertion.confidence`；改算法不改 `algo_version`；`inputs_hash` 留空；指标只写自然语言不写可执行 SQL。

## F · Schema 版本号怎么定
| 段 | 触发操作 | 例子 |
|---|---|---|
| PATCH | 只改元数据 | 改 `description`、补 `aliases`/`external_mapping`、改 `sort_order` |
| MINOR | 加字段/枚举值/实体/派生特征，旧代码不改仍能跑 | 场景 A、B、C、E |
| MAJOR | 破坏性：改列类型、改字段语义、改 code 含义、拆并表 | `birth_year` 改为完整生日；F01 含义变更 |

口诀：**"旧代码不改还能跑吗？"能→MINOR，不能→MAJOR**；拿不准按 MAJOR（新增列+双写+弃用旧列）。
两个版本号的关系：`field_catalog.version` 是**字段自己的版本**；记录级 `schema_version` 是**该记录写入时所处的 schema 版本**，加字段后老记录保持旧版，同表内 1.0.0 与 1.1.0 并存是正常且有意义的。代码表另有独立 `code_table.version`。
```sql
SELECT schema_version, count(*) FROM person GROUP BY 1 ORDER BY 1;   -- 版本分布，勿全表改写
```
**反例**：加字段后全表 `UPDATE schema_version`（抹掉写入规则信息）；改字段语义只升 MINOR（口径混用）；把版本当 commit 号；CSV 与库不一致。

## G · 字典导出与对外发布
先建目录 `mkdir dist\catalog`；数据库需以 `psql` 连接（`\copy` 是 psql 元命令，不是 SQL）。
```sql
\copy (SELECT field_id,entity_id,title,data_type,unit,value_range,code_table_id,cardinality,collection_method,applies_to,derivation,strata,access_tier,status,version,owner FROM field_catalog ORDER BY entity_id,field_id) TO 'dist/catalog/field_catalog.csv' WITH (FORMAT csv, HEADER true, ENCODING 'UTF8')
\copy (SELECT code_table_id,code,label_zh,label_en,parent_code,level,sort_order,definition,aliases,external_mapping,effective_from,effective_to,deprecated,replaced_by FROM code_value ORDER BY code_table_id,sort_order) TO 'dist/catalog/code_value.csv' WITH (FORMAT csv, HEADER true, ENCODING 'UTF8')
\copy (SELECT jsonb_pretty(jsonb_build_object('@context',jsonb_build_object('@vocab','https://schema.org/','cr','http://mlcommons.org/croissant/'),
 '@type','cr:Dataset','name','MedTalent KB 数据字典','version','1.1.0',
 'description','医学生人才信息库字段目录与受控词表',
 'license','https://creativecommons.org/licenses/by-nc/4.0/','datePublished',to_char(now(),'YYYY-MM-DD'),
 'distribution',jsonb_build_array(jsonb_build_object('@type','cr:FileObject','name','field_catalog.csv','contentUrl','dist/catalog/field_catalog.csv','encodingFormat','text/csv')),
 'recordSet',jsonb_build_array(jsonb_build_object('@type','cr:RecordSet','name','field_catalog',
   'field',(SELECT jsonb_agg(jsonb_build_object('@type','cr:Field','name',field_id,'dataType',data_type) ORDER BY field_id) FROM field_catalog WHERE status='active'))))) TO 'dist/catalog/dataset.jsonld'
```
```powershell
cd D:\wbo-workspace\medtalent-db
Get-ChildItem dist\catalog\*.csv,dist\catalog\*.jsonld | Get-FileHash -Algorithm SHA256 |
  ForEach-Object { "{0}  {1}" -f $_.Hash.ToLower(),(Split-Path $_.Path -Leaf) } |
  Tee-Object -FilePath dist\catalog\checksums.sha256
```
```sql
INSERT INTO change_log (actor,object_type,object_name,change_type,from_version,to_version,detail)
VALUES ('ops','dataset','medtalent-catalog','add','1.0.0','1.1.0',
 '{"artifacts":{"field_catalog.csv":"<sha256>","dataset.jsonld":"<sha256>"}}'::jsonb);

INSERT INTO dataset_release (release_id,name,version,description,published_at,
  doc_guide_uri,doc_codebook_uri,checksum_sha256,status)
VALUES ('dsr_catalog_1_1_0','MedTalent KB 数据字典','1.1.0','字段目录与受控词表公开版',
  now(),'docs/07-数据字典与扩展机制.md','dist/catalog/field_catalog.csv','<sha256>','published');
```
**发布条件：无 codebook 不发布**——`chk_release_needs_codebook` 已用 CHECK 强制（`status<>'draft'` 且 `doc_codebook_uri` 为空即报错）。
**验证**：`SELECT release_id,status FROM dataset_release WHERE status<>'draft' AND coalesce(doc_codebook_uri,'')='';` 应 0 行；`SELECT count(*) FROM field_catalog WHERE status='active';` 应与导出的 CSV 数据行数相等；重算哈希比对 `checksums.sha256`，任一不一致即文件被改动。
**反例**：绕过 CHECK 强行 published；只发 CSV 不发哈希；导出不 `ORDER BY`（无法 diff）；把 T3 字段值混进公开字典。

## 8 · 质检门
**跑法**：`cd D:\wbo-workspace\medtalent-db; python code\validate_catalog.py .` —— 退出码 0=无 ERROR 可入库，1=禁止入库。
**检查项**（读 `code/validate_catalog.py`）：① 表头逐列相等、行内列数一致、主键非空不重复（ERROR）；② `parent_code` 必须同 `code_table_id` 内存在（ERROR）；③ `field_catalog.code_table_id` 须在 CSV 代码表集合内（ERROR，不查库）；④ `data_type`/`cardinality`/`access_tier` 受控（ERROR）；⑤ `cardinality=array` 而 `data_type` 非 array/json（WARN）；⑥ `data_type` 误写 `derived`（WARN）；⑦ 数值型无 `unit` 又无 `value_range`（WARN）；⑧ 废弃值缺 `replaced_by`、`external_mapping` 为空（WARN）；⑨ `collection_method` 非常规（WARN）。
**失败了怎么办**：报错形如 `schema\catalog\field_catalog_seed.csv 第 76 行列数 18 != 17`，行号是 CSV 物理行号（第 1 行为表头）。列数不符九成是格子内写了半角逗号未加引号，整格加双引号、格内双引号写两个：
```csv
F_PERSON_ONLY_CHILD,person,是否独生子女,"用于家庭资源与流动意愿分析,含收养情况",boolean,,,scalar,questionnaire,,,"",,"T2",active,1.0.0,research
```
`parent_code 不存在`→确认父码在同一 `code_table_id` 下（大小写敏感）；`引用未定义的 code_table`→该表在 `code_table_seed.csv` 里一行都没有。修到 `错误：0`，警告逐条判断，**不许关规则**。
**纪律**：任何对两个 seed CSV 的改动之后必须重跑，结果写进变更说明；质检门只管种子 CSV，数据库侧用 `information_schema` 补位，两边都绿才算完成。

## 9 · 一页速查表
| 需求形态 | 机制 | 改哪些对象 | 耗时 | 改表结构 |
|---|---|---|---|---|
| 多/废一个枚举值 | A | `code_value`+seed CSV | 10 分钟 | 否 |
| 普通标量字段 | B | `attribute_definition`+`field_value`+`field_catalog` | ≤30 分钟 | 否 |
| 高频过滤字段 | D promote | `ALTER TABLE`+回填+弃用+`change_log` | 半天 | 是 |
| 新实体 | 建表 | `entity_catalog`+`CREATE TABLE`+`field_catalog`+`change_log` | ≤1 天 | 是（新表） |
| 探索期新维度 | C | `assertion` | 5 分钟 | 否 |
| 人级派生指标 | `derived_feature` | 插值+`algo_version`+`inputs_hash` | 1–2 小时 | 否 |
| 族级聚合指标 | `metric_definition` | 登记 SQL+版本 | 1 小时 | 否 |
| 改元数据 | 直接改 | `field_catalog`/`code_value` | 5 分钟 | 否（PATCH） |
| 改类型/语义 | MAJOR | 新增列+双写+弃用 | 1–2 天 | 是 |
| 对外发布 | G | CSV/JSON-LD+sha256+`dataset_release` | 2 小时 | 否 |

**每个场景收尾三步**：① 改 CSV 或库；② `change_log` 留痕（`from_version`/`to_version`/`detail`）；③ 重跑质检门，确认 `错误：0`。
