**【推荐】三层骨牌映射**
1. **全球锚**：以 ISCO-08 4 位 unit group 作跨体系唯一锚点（SOC/NOC/SSOC/ESCO 均可回溯），字段 `isco08_code`。
2. **中国合规层**：以《大典》细类码为本地口径（招聘、社保、地方人才政策均用它），字段 `cn_occode`。大典↔ISCO-08 **无官方对照表**，须自建并逐条标注置信度。
3. **任务层**：用 O*NET-SOC 的 `.xx` 细分承载"同职业不同岗位族"（内科医师 vs 心内介入医师），字段 `onet_soc_code`。
> **关键风险**：医学职业在 ISCO-08 中粒度严重不足——医生集中于 2211/2212（全科/专科），中国临床分级（住院医师/主治/副主任）与专科方向必须靠本地字段 + O*NET 细分补齐，**不能指望职业码本身**。

**来源**：ESCO [skills pillar](https://esco.ec.europa.eu/en/about-esco/escopedia/escopedia/skills-pillar)、[skill reusability level](https://esco.ec.europa.eu/en/about-esco/escopedia/escopedia/skill-reusability-level)；O*NET [overview](https://www.onetcenter.org/overview.html)、[content model](https://www.onetcenter.org/content.html)、[Transferable Skills 2.B](https://www.onetonline.org/find/descriptor/browse/2.B)；Lightcast [Skills Taxonomy](https://kb.lightcast.io/en/articles/7216059-lightcast-skills-taxonomy)；DigComp [ESCOpedia](https://esco.ec.europa.eu/en/about-esco/escopedia/escopedia/european-digital-competence-framework-citizens-digcomp)；European Learning Model [ESCOpedia](https://esco.ec.europa.eu/en/about-esco/escopedia/escopedia/european-learning-model)。

**【事实·最核心一条】** ESCO 的 **skill reusability level** 正回答本项目命题"如何用词表表达**能力**而非**专业**"，四级为：**Transversal**（跨广泛职业与部门，即 core/basic/soft skills，例："work in teams"、"communication"）→ **Cross-sectoral**（跨若干部门）→ **Sector-specific**（一个部门内多职业）→ **Occupation-specific**（单一职业内）。并另有 **essential / optional** 区分该职业"必需 / 可选"。

**【推荐】"能力词表"四原则**
1. **用可观察行为动词短语命名**，不写学科名：写 `communicate clinical findings to non-specialists`，不写 `内科学`（后者归 `knowledge`）。
2. **显式区分 skill 与 knowledge**（ESCO 的 `skill_type`）："专业"落 knowledge，"能力"落 skill/competence，匹配时权重不同。
3. **每条能力必须带 reusability level**——这是计算"跨行业迁移距离"的直接依据（transversal 权重最高、occupation-specific 最低）。
4. **用 hidden terms 承接口语化表达**（简历 vs JD 用词差异），避免同义写法重复建概念。

## ④ JD 结构化字段规范草案

**【事实】** `schema.org/JobPosting` 是主流结构化招聘标记（Google Jobs 收录规范），核心属性：`title`、`description`、`datePosted`、`validThrough`、`hiringOrganization`、`jobLocation`、`jobLocationType`（如 `TELECOMMUTE`）、`employmentType`、`baseSalary`、`educationRequirements`、`experienceRequirements`、`skills`、`qualifications`、`responsibilities`、`occupationalCategory`、`industry`、`jobBenefits`；必填为 `datePosted` + `description` + `hiringOrganization` + `jobLocation`（或远程）+ `title`。**来源**：[Google Search Central — JobPosting structured data](https://developers.google.com/search/docs/appearance/structured-data/job-posting)。

**【事实】** 简历侧：HR Open Standards（由 HR-XML 演进）的 Recruiting/Resume 规范以 XML/JSON 定义 `PersonName / ContactInfo / EmploymentHistory / EducationHistory / Competency` 等；JSON Resume 为社区 JSON Schema（`basics / work / volunteer / education / awards / certificates / publications / skills / languages / interests / references / projects`）；Europass 与 European Learning Model 承载欧洲学历与微证书。**来源**：[HR Open Standards](https://www.hropenstandards.org/)、[JSON Resume Schema](https://jsonresume.org/schema/)、[European Learning Model](https://esco.ec.europa.eu/en/about-esco/escopedia/escopedia/european-learning-model)。

**【事实】** O*NET **Job Zone** 按"教育 / 相关经验 / 在职培训"把职业分 5 区，并给出 SVP 区间：Zone 1-2（极少至少量准备，SVP<6.0）、Zone 3（中等，6.0–<7.0）、Zone 4（相当多，7.0–<8.0）、Zone 5（大量，≥8.0，例：药师、医师助理）。**来源**：[O*NET OnLine — Job Zones](https://www.onetonline.org/help/online/zones)。

**【推荐】`job_posting` 字段草案**（在 schema.org 之上补齐"必备/加分、硬性/软性、可替代路径"三个匹配必需维度）

```
job_id                 string PK
source / source_url    string          原始渠道与原文链接（可追溯）
title_raw / title_normalized
occupation_codes       array<code>     {system: isco08|cn_occode|onet_soc, code, confidence}
job_family_id          FK             岗位族（自建，如"临床研究/CRO"）
job_level              enum            intern|entry|junior|mid|senior|lead|principal
job_zone               int 1-5         O*NET Job Zone
employment_type        enum            FULL_TIME|PART_TIME|CONTRACT|INTERNSHIP|TEMPORARY
location / remote_type string / enum   onsite|hybrid|remote
salary_min / max / currency / period
education_required     {level: enum(对齐 ISCED), field: array<code>, strict: bool}
experience_required    {min_years, max_years, domain: array<code>}
certifications_required array<code>    执业医师资格证、规培合格证、GCP…
skills_required        array<{skill_uri, weight, mandatory: true,  substitutable_by: array<skill_uri>}>
skills_preferred       array<{skill_uri, weight, mandatory: false}>
competencies_required  array<{competency_id, canmeds_role, min_level, evidence_min: E0..E4}>
responsibilities       array<text>     → 可编码为 O*NET DWA / IWA
education_substitution array<rule>     "经验可替代学历/专业"的可替代路径
language_required      array<{lang, cefr_level}>
raw_text / parsed_at / parser_version / parse_confidence
```

**【推荐】无损解析判别规则**
- **必备 vs 加分**：原文情态词映射——"须/必须/要求/持有/具备"→ `mandatory:true`；"优先/加分/熟悉者优先/有…者更佳"→ `mandatory:false` 并写入 `skills_preferred`。**模棱两可时默认按 preferred 处理并下调 `parse_confidence`**：宁可漏判必备，不可误判必备。
- **硬性 vs 软性**：硬性=可被证书/学历/年限机器验证（落 `certifications/education/experience`）；软性=需评估或作品验证（落 `competencies`）。
- **可替代路径必须显式建表**：本项目最大价值在"非典型路径"（基础医学博士转医学事务、护理转临床研究协调）。若只做"满足/不满足"二元判断，会把大量可匹配候选人判死。

## ⑤ 受控词表与编码建议

**【推荐】架构：一套 SKOS 词表 + 三张映射表 + 一张证据表**

1. **命名与标识**
   - 概念 ID 用**稳定 URI**，不用自增整数。若直接复用 ESCO，存 `data.europa.eu/esco/skill/{uuid}` 作外键（ESCO 官方 URI 模式），本地只加中文标签。
   - 每概念必备字段：`prefLabel_zh`、`prefLabel_en`、`altLabels[]`、`hiddenLabels[]`、`definition`、`scopeNote`、`skill_type ∈ {knowledge, skill}`、`reusability_level ∈ {transversal, cross_sectoral, sector_specific, occupation_specific}`、`status ∈ {active, deprecated, proposed}`、`broader/narrower`。

2. **编码与层级**
   - 职业主键三元：`isco08_code`（全球锚）+ `cn_occode`（大典细类）+ `onet_soc_code`（可含 `.xx`）。
   - **技能不建"专业树"作主干**：主干用 `reusability_level`；医学专业方向由 `knowledge` 概念 + 职业码承载。这样"沟通能力"在临床、CRO、保险三处是**同一个 skill URI**，迁移计算才成立。
   - **能力（胜任力）单建一套 competency 词表**，粒度 = CanMEDS 七角色 / ACGME 六域 / 中国住培核心胜任力，字段 `canmeds_role`、`acgme_domain`、`cn_residency_domain`（多对多）。

3. **映射表**（独立成表，禁止写死在职业记录里）
   `occupation_crosswalk(source_system, source_code, target_system, target_code, mapping_confidence, valid_from, valid_to)`；`skill_crosswalk(local_skill_id, esco_uri, onet_element_id, confidence)`。置信度枚举沿用 SKOS 映射关系：`exactMatch / closeMatch / broadMatch / narrowMatch / relatedMatch / unmapped`。

4. **"能力–证据–岗位"三元关系**

```
capability(id, pref_label, skill_type, reusability_level, canmeds_role[])
evidence(id, capability_id, person_id, evidence_type, cel_level, issuer, issued_at,
         verifiable_url, artifact_ref, expiry_at, verified_by, verified_at)
position_requirement(job_id, capability_id, weight, mandatory, min_cel_level, min_proficiency)
person_capability(person_id, capability_id, proficiency, source_evidence_id[], confidence, last_used_at)
```

- **`evidence` 是唯一可信来源**，`person_capability.proficiency` 必须由证据推导，或标注为 self-report。
- **三元关系的本质**：`person_capability × position_requirement` 在 `capability` 维度上的**加权覆盖**，再乘 `evidence.cel_level` 的**可信度折扣**——`匹配分 = Σ(weight × 覆盖度) × f(证据等级)`。这条公式把"简历写了"与"有作品/有履职记录"区分开，是商业库区别于关键词匹配的关键。
- **能力等级口径**统一为 `0 未具备 / 1 了解 / 2 在指导下可完成 / 3 独立完成 / 4 可指导他人 / 5 可定义标准`（对 DigComp 8 级与 Dreyfus 模型的粗粒度裁剪，属**本研究推荐**）。

5. **版本治理**：所有来源体系都带版本（大典 2022、ISCO-08 修订至 2030、ESCO v1.2.1、NOC 2021 V1.0、O*NET 季度版）。对照表与每条映射须有 `valid_from/valid_to`；**禁止静默改写**，退役用 deprecated + replacedBy 表达。

## 落地优先级（**推荐**）

1. 先立 **ISCO-08 4 位 + 大典细类**双码，覆盖中国合规与全球对标（暂时接受医学粒度不足）。
2. 引入 **ESCO skills URI 作技能主键**（免费、LOD、自带 essential/optional 与复用层级）；仅对医学专有概念自建扩展并标 `unmapped`。
3. 以 **CanMEDS 七角色 + 住培核心胜任力**建 competency 词表，落实第 ③ 节 10 条可迁移能力；可迁移能力组直接借用 O*NET Transferable Skills（2.B）五组分类。
4. JD 解析器先做 `mandatory/preferred` 判别与 skill URI 归一，再做 substitution 规则（价值最高、也最难，须人工标注种子集）。
5. 证据表（`evidence` + `cel_level`）优先于评分算法——**没有证据分级，评分不可审计**。
