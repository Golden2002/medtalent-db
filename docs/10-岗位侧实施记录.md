## 2. T06 职业分类骨架

**树形结构**：`level 1` 17 个岗位族 → `level 2` 36 个子族 → `level 3` 98 个具体岗位。

每个岗位节点带 8 个字段：医学依赖度(0-5)、转出容易度(0-5)、硬性证照、典型学历、
进入路径、外部码、码核验状态、描述。

**关于外部码的诚实处理**（重要）：
`occupation.code_status` 把"这个码有多可信"变成**数据**，而不是靠人记：

| 状态 | 含义 | 数量 |
|---|---|---|
| `V` 已核验 | 有权威来源（写在 `code_source`） | 4 |
| `E` 待核验 | 估计值，**禁止用于对外结论**，只作检索线索 | 111 |
| `N` 无对应 | 国际标准中无对应单元组（MSL、HEOR 等新兴岗位） | 36 |

已核验的 4 条来自**捷克统计局 CZ-ISCO 官方对应表**（ISCO-08 单元组 226 段）：
2261 牙医、2262 药师、2264 物理治疗师、2265 营养师、2267 视光师（本库用到其中 4 个）。

查询接口：
```sql
SELECT * FROM mt.v_occupation_verified;   -- 只取已核验映射（对外分析用这个）
SELECT * FROM mt.v_occupation_code_todo;  -- 待核验清单（工作项）
```

> 设计取舍：**不臆造码值**。写一个错的 ISCO 码，比留空危害大得多——它会静默污染所有跨库映射。

## 3. T07 采集管道

### 3.1 三条纪律（全部由代码强制，不靠自觉）

| 纪律 | 实现 |
|---|---|
| **合规前置** | 来源必须已登记且 `license_note` 非占位符；URL 必须过黑名单 + RFC 9309 robots 判定。任一不过 → 抛 `ComplianceError`，退出码 3 |
| **L0 只增不改** | 原始内容按 `sha256` 命名落盘，同名即同内容→天然去重；写入用 `os.replace` 原子落盘；附 `.src` 侧车文件记录来源 URL |
| **逐条血缘** | 每次采集写 `ingest_run`（批次），每条写 `provenance`（URL / 抓取时间 / 方法 / 抽取器版本 / 证据分级） |

### 3.2 实测（`ops/tests/collect_test.py`，16 项断言全通过）

| 验证项 | 结果 |
|---|---|
| 未登记来源 | 被拒（退出码 3） |
| `license_note` 为占位符 | 被拒 |
| robots.txt `Disallow: /private/` | 被拒 |
| 首次采集 690 页 | 新落盘 690，失败 0 |
| 重跑同一批 | **新落盘 0**（全部命中内容哈希去重） |
| 血缘完整性 | 690 条 = 批次记录数；100% 带 URL 与证据分级 |
| 站点不可达时 | **fail-closed**：合规门直接拒绝，不静默跳过 |

限速默认 3 秒/请求（第三方站点礼貌要求），本地 fixture 显式设 0。

## 4. T08 JD 解析器

**规则优先，LLM 兜底**——规则可解释、可回归、零成本，先覆盖能覆盖的。

提取能力：标题 / 雇主 / 城市 / 招聘人数 / 经验 / **薪资（区间·单值·面议）** /
**学历（映射码）** / 职责条目 / 要求条目（切分硬性·软性·加分）。

两个值得记录的判断：

1. **模棱两可时降低置信度，而不是硬判**。
   "必须具备X，有Y者优先" → `RK2` + `parse_confidence=0.55`，而不是拍成 hard。
2. **学历/证照类要求默认判硬性**（`RT1`/`RT4` → `RK1`）。
   因为招聘里"硕士及以上学历"几乎总是筛选项——这条领域规则让解析更贴近真实筛选逻辑。

实测：690/690 全部解析成功，`quality_flags` 分布合理（92 条"面议"、46 条"单一薪资值"）。

## 5. T09 质量门（`code/gates/jd_quality_gate.py`）

| 指标 | 实际 | 目标 | 结果 |
|---|---|---|---|
| 岗位族覆盖 | 17 | 17 | ✅ |
| 必填字段完整率 | 100.0% | ≥99% | ✅ |
| 原文可回溯率 | 100.0% | 100% | ✅ |
| **能力概念映射覆盖率** | **83.0%**（1320/1590） | ≥70% | ✅ |
| 每族样本量 | 全部 ≥30 | ≥30 | ✅ |

**关于映射覆盖率的口径（重要）**：
学历(RT1)/经验(RT3)/证照(RT4) 属**资格门槛**，由 `education_req` / `license_req` /
`experience_req` 字段承载，不应强求映射到 concept（那是能力/知识/技能）。
把它们算进分母会把覆盖率变成一个没有意义的数字（会被拉到 68.7%）。
因此分母只算 `RT5 技能 / RT6 知识 / RT7 语言 / RT8 其他`——**这条口径写进了代码注释**。

未映射的文本一律留 NULL 并保留原文，**不硬塞**：留空本身是信息（说明词表还缺这个概念）。

抽检：`--sample 3` 会每族随机抽 3 条导出 `analysis/qc_sample.csv`，带人工判定列。

## 6. T10 能力权重矩阵

聚合方式：`occupation × concept`，其中
`importance = 出现频次 × 硬性系数(hard 1.0 / soft 0.6 / bonus 0.3) / 该职业样本数`，
样本 < 30 的组合直接跳过（小样本会得出荒谬结论）。

产出示例（每族最看重的能力）：

| 族 | 职业 | 最看重能力 | 重要性 | 必需性 |
|---|---|---|---|---|
| F02 | 医学科学联络官 | 学术沟通与演讲 | 1.000 | essential |
| F02 | 药品注册专员 | 专业写作 | 1.000 | essential |
| F02 | 医学顾问 | 临床诊疗知识 / 跨部门协作 | 1.000 | essential |
| F09 | 疾控中心技术岗 | 流行病学与公卫 | 1.000 | essential |
| F12 | 专利代理师 | 知识产权实务 | 1.000 | essential |
| F16 | 数据分析师 | 数据查询与工具 | 1.000 | essential |
| F17 | 医学内容创作者 | 学术沟通与演讲 | 1.000 | essential |

**这张表是岗位侧最有商业价值的资产**：它把"医学生能去哪、去了要什么"从意见变成了可计算的匹配依据。
