# 演示站点

这个目录里有**四种**演示，它们回答的问题不同，别混在一起看：

| 文件 | 什么形态 | 回答的问题 | 启动 |
|---|---|---|---|
| `app.py` | 可交互表单站点 | 每个字段 n 个选项 → 用户选择 → 入库；现场加维度（零 DDL） | `python code\demo\app.py --serve`（:8080） |
| `console.py` | 业务控制台（8 页） | **这个产品能做什么**：岗位图谱、能力矩阵、匹配、小程序接入、备份 | `python code\demo\console.py --serve`（:8081） |
| `portal.py` | **只读数据门户（13 页）** | **这个数据库长什么样**：人才库/职业库/职业树/匹配/扩展与演化/质量，以及表、约束、真实行、检索、分析、只读 SQL | `python code\demo\portal.py --serve`（:8082） |
| `portal_dev.py` | **开发者模式（可写，6 页）** | 在线开发：SQL 控制台、动态建模、运维工具、审计、迁移 | `python code\demo\portal_dev.py --serve`（:8083） |
| `static_site.py` | 单文件静态 HTML + PDF | 可以离线发出去的总体介绍 | `python code\demo\static_site.py` |

`console.py` 是**业务**演示，`portal.py` 是**数据**演示，`portal_dev.py` 是**开发**演示。
客户说"我想看看数据库本身"时开 :8082；要现场做点什么（加字段、加行、跑重算）开 :8083。

**读写为什么分两个进程**：门户的一半价值在于"它证明自己只读"——
`ops/tests/portal_test.py` 用审计流水（遍历全部页面后 `change_log` 不增长）和
`SELECT 1 INTO t` 被 PostgreSQL 只读事务拒绝来证明。同一个进程里只要有能写的路由，
这条证明就没了。所以 :8082 任何配置下都写不进去。

## 一、动态表单站点（`app.py`）

用 mock 数据演示三件事：**加列零 DDL、建行零 DDL、每字段 n 个选项全部来自数据库**。

## 启动

```powershell
cd D:\wbo-workspace\medtalent-db
python ops\pg.py start                # 确保数据库在跑
python code\demo\app.py --seed 30     # 造 30 条 mock 档案
python code\demo\app.py --serve       # 打开 http://127.0.0.1:8080
```

只监听 `127.0.0.1`，不对局域网暴露。`Ctrl+C` 停止。

## 页面上能做什么

| 区域 | 说明 |
|---|---|
| ① 填写一份画像 | 每个字段的候选选项实时从 `code_value` 读取；单选=下拉框，多选=复选框，数值=数字框 |
| ② 现场新增一个维度 | 填标题 + 逗号分隔的 n 个选项，提交后**刷新页面表单立刻多出这个字段**（不执行任何 DDL） |
| ③ 字段与候选选项 | 数据库视角的当前表单定义 |
| ④ 已入库画像 | 显示每个档案的画像维度（含刚动态加的列） |
| 维护 | 一键清除演示数据（档案 + 维度 + 词表） |

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 表单页面 |
| GET | `/api/form-schema?entity=person` | 表单 JSON（字段 + n 个选项），供任何前端消费 |
| POST | `/submit` | 提交画像，写入数据库 |
| POST | `/dimension` | 新增一个维度（列） |
| POST | `/reset` | 清除演示数据 |

`/api/form-schema` 返回结构见 `docs/09-动态建模与前端表单方案.md` §4.2。

## 演示数据的命名约定

| 前缀 | 含义 |
|---|---|
| `per_demo_*` | 演示档案 |
| `F_DEMO_*` | 预置演示维度 |
| `F_CUSTOM_*` | 页面上现场新增的维度 |
| `CT_F_DEMO_*` / `CT_F_CUSTOM_*` | 上述维度对应的词表 |

`--reset` 会按这些前缀清理，**不会碰任何真实数据**。

## 数据写在哪

| 内容 | 表 |
|---|---|
| 档案主体（person_id / subject_code / 入组渠道） | `person` |
| 人口学字段（性别等，属于另一实体） | `field_value`（subject_type=`person_demographics`） |
| 所有动态维度与自定义维度的取值 | `field_value` |
| 字段定义 | `field_catalog` |
| 选项（n 个给定内容） | `code_table` + `code_value` |
| 变更留痕 | `change_log` |

## 已验证

`python ops\tests\form_server_test.py` —— 30 项断言全通过，覆盖：
首页渲染 → schema 接口 → 页面新增维度 → **断言行数/列数未变（零 DDL）** → 模拟提交 →
按码入库校验（单选/多选/数值/跨实体）→ 非法选项被拒 → 一键清理。

另见 `python ops\tests\dynamic_model_test.py` —— 28 项断言，覆盖纯值实体、维度软删除、数据不丢。

## 二、数据库门户（`portal.py`）

**只读**。它不写数据库——这是设计约束，不是"暂时没做写"。

```powershell
python ops\pg.py start
python code\demo\portal.py --serve     # http://127.0.0.1:8082
python code\demo\portal.py --check     # 自检：元数据 + 每个页面渲染一遍，不开服务
python code\demo\portal.py --tables    # 命令行列出全部表/视图与精确行数
```

### 页面

| 路由 | 内容 |
|---|---|
| `/` | 库的名片：表/列/行/外键/索引/触发器/码值/字段的真实规模；按 8 个域分组；单表行数排行 |
| `/talent` | **人才库 + 在线分析**：筛选（学历/专业/省份/能力）+ 6 个实时分析 + 人才清单 |
| `/talent/<person_id>` | **人才档案**：基本信息、教育/工作/临床/证书/项目/成果/获奖/偏好、能力主张（带证据与可迁移性）、匹配结果、观测窗口 |
| `/occupations` | **职业库 + 在线分析**：6 个实时分析 + 职业节点清单（可按族与层级筛选） |
| `/occupation/<id>` | **职业详情**：全部字段 + 能力要求（重要性/必需性/样本）+ 子节点 + 关联 JD + 迁移记录 + 变更记录 |
| `/tree` | **职业树浏览器**：层级展开、节点徽章（外部码/能力项/JD 数）、**as-of 时间旅行**、时点对比 |
| `/match` | **能力-职业匹配**：按人才看（met/gap/unknown 三态拆解）或按职业反查（哪些人最合适）；缺口 → 目标要求强度 |
| `/extend` | **扩展与演化**：三条扩展机制 + 各自在库里的使用痕迹；职业树生长；能力-职业映射的版本化与漂移 |
| `/quality` | **数据质量仪表盘**：完整性不变量、岗位侧质量门、表填充率、列空值率、数据新鲜度、审计流水、备份健康、访问策略、发布登记 |
| `/schema` | 78 张基础表 + 14 个视图，按域分组，含列数、**精确**行数、约束数、索引数、触发器数 |
| `/t/<表>` | 列定义 / **完整约束定义**（外键目标可点）/ 索引 / 触发器 + 真实数据（分页、排序、按列筛选、CSV 导出）/ **本页执行的 SQL** |
| `/e/<表>?val=<主键>` | **实体页**：一行记录的全部字段 + 所有通过外键指向它的表（含行数与前几行样本） |
| `/search?q=` | 跨 7 个数据源的关键词检索 + 表名列名的元数据检索；每条命中标明来自哪张表 |
| `/analyze` | 8 个预置分析，每个都显示它执行的 SQL，可导出 CSV |
| `/sql` | 只读 SQL 控制台 |
| `/lineage` | 来源登记 → 采集批次 → 逐条血缘 → 磁盘上的 L0 原始文件 |
| `/dev` | 开发者模式入口（说明它在 :8083；这一页本身只读） |

### 演示动线（约 6 分钟）

1. `/` 先看规模：**78 张表、1,120 列、14.8 万行**，并且说明这是 `count(*)` 不是估算。
2. `/talent` 看人才库：筛选 + 6 个在线分析；点进一个人看完整档案与能力主张。
   注意页面上**合成数据会被标注**，以及"无教育记录"的行如实显示为无。
3. `/occupations` 选一个非临床岗位（如医学科学联络官），看它到底要什么能力。
4. `/tree` 看职业树，拖一个 as-of 日期看"当时的树"。
5. `/match` 重点讲 **unknown 不是不合格**。
6. `/extend` 讲结构怎么长（三条机制 + 使用痕迹），以及能力-职业映射的**版本化**。
7. `/quality` 用可核的数字收尾：完整性不变量、覆盖率、填充率、备份健康。
8. `/dev` 起开发者模式，现场加一个维度、建一行、写一个值——**注意证据表里
   "基础表数量"和"person 列数"始终显示"不变"**，这就是"零 DDL"。
9. `/sql` 故意写 `DROP TABLE person` 试试，会被拒；写 `SELECT 1 INTO t`，
   会被 PostgreSQL 的只读事务拒。

### 三条设计纪律

| 纪律 | 为什么 |
|---|---|
| **全站只读**，写操作由**数据库层**拒绝 | 门户是给客户看的，不能有任何改数据的可能。文本过滤只是提前给好错误信息，真正的防线是 `BEGIN TRANSACTION READ ONLY` |
| 行数一律 `count(*)`，不用 `reltuples` | 实测 `reltuples` 会过时（`code_table` 估算 53、实际 49）。显示估算值就违背了"看到真实的样子" |
| 表名/列名先与系统目录比对，再用 `sql.Identifier` 转义 | URL 里的表名是用户输入，不能直接拼进 SQL |

### 已验证

`python ops\tests\portal_test.py` —— **69 项断言**，包括：

- 页面上显示的行数 == 库里 `count(*)` 的结果（抽查 5 张表）
- 外键链接**不是死链**：抽验链接指向的记录在目标表里确实存在
- 分析页的口径与直接执行同样 SQL 的结果一致
- CSV 导出行数 == 库里行数；带 BOM
- 未知表 → 404、未知列 → 400、不存在的实体 → 404（不是 500，也不静默降级）
- **遍历全部 92 个对象的页面后 `change_log` 未增长**——门户确实一个字节都没写
- `SELECT 1 INTO t` 被 PostgreSQL 只读事务拒绝，且探测表没有被创建

> 过程中修掉的真问题（都是只有真跑才暴露的）：
> ① `SET LOCAL statement_timeout = %s` —— PostgreSQL **不接受 `SET` 用参数占位符**，
> 扩展协议会把它发成 `$1` 导致语法错误；
> ② 外键单元格一开始只渲染了链接，把 `FOREIGN KEY (...) REFERENCES ...` 定义丢了，
> 而定义本身才是"这个库有哪些不变量"的证据；
> ③ 数据表被超长列撑高，一行看不清一条记录（现在单行 + 省略号，完整值在 `title` 里）；
> ④ 职业树页的"一年前"显示 0 节点——那是对的（种子节点 `valid_from = 2026-01-01`），
> 但标签不带日期就像 bug。现在标签带实际日期，并明确写"0 不是出错，是那时它还不存在"。

## 三、开发者模式（`portal_dev.py`，:8083，**可写**）

```powershell
python ops\pg.py start
python code\demo\portal_dev.py --serve    # http://127.0.0.1:8083
python code\demo\portal_dev.py --check    # 自检：渲染各页 + 验证"试运行必须回滚"
```

### 页面

| 路由 | 内容 |
|---|---|
| `/` | 库信息（版本/大小/连接数/扩展/字符集）、演化层健康度、开发能力清单、当前结构计数 |
| `/sql` | **可写 SQL 控制台**：多语句、单事务、**默认试运行（执行后回滚）**、勾选提交才落地、逐条给出影响行数与结果集 |
| `/model` | **动态建模**：`add_dimension` / `create_instance` / `set_value` / `deprecate_dimension` / `register_entity`，每次操作后给出**证据表** |
| `/tools` | **运维工具**：一键驱动既有 CLI，并可选跑指定回归套件 |
| `/audit` | `change_log` 最近 60 条 + 按对象类型统计 |
| `/migrate` | 12 个迁移文件清单（含"是否已应用"粗判）+ schema 对象统计 |

### 三条设计选择

| 选择 | 理由 |
|---|---|
| **读写分成两个进程** | 门户的一半价值是"它证明自己只读"。同进程里存在写路由，这条证明就没了 |
| **写操作只走 POST**，GET 只渲染表单 | 否则浏览器预取、爬虫或被误点的示例链接就可能改库。示例链接现在只"填入表单" |
| **SQL 默认试运行后回滚** | 先看到逐条影响行数，确认无误再勾选提交。比"点下去就改"安全得多 |
| **运维工具不重写业务逻辑** | 只驱动 `code/`、`ops/` 下已被回归测试覆盖的 CLI，输出原样回显 |

`/model` 的"证据表"是这一页的核心：每次操作都对比
**基础表数量**、**person 表列数**、已登记字段、属性定义、表单 schema 行数、代码值。
前两个必须**不变**——这就是"加字段/加行没有做 DDL"的证据。

### 已验证

`python ops\tests\devmode_test.py` —— **39 项断言**，包括：

- **GET 带写语句和 `commit=1` 也不会建表**（写操作只走 POST）
- POST 未勾选提交 → 页面显示"已回滚"，且表确实不存在
- POST 勾选提交 → 表建出来了，影响行数属实（2 行就是 2 行），随后清理
- 加一个带 3 个选项的维度 → **基础表 78→78、person 列数 16→16**、
  已登记字段 112→113、代码值 305→**308**（3 个选项各一行）、表单 schema 立刻可见
- `create_instance` 建记录 + `set_value` 写值 → 库里能查到，存的是**选项码**不是标签
- 写入未定义的选项码 → 被 `assert_option` 拒绝
- 写未登记的 `attrs` 键 → 被数据库拒绝，且没有留下记录
- 运维工具真的驱动 CLI（输出里有"错误：0"）；未知工具被拒
- 结束时校验测试数据**零残留**

> 测试写错过一次：我断言"代码值 +1"，实际加了 3 个选项 → +3。
> 是测试的假设错，不是代码错——修的是断言。
