| 项 | 值 |
|---|---|
| 公网地址 | **https://minerals-graphics-temporary-dated.trycloudflare.com** |
| 暴露的服务 | **只读门户**（本机 `127.0.0.1:8082`） |

## 1.1 已决定：**公网只读，管理只在本机**（用户决策）

需求②同时提到"浏览"和"管理"。经确认，采取：

| 能力 | 在哪做 | 怎么保证 |
|---|---|---|
| **浏览数据** | 公网（上面的地址） | 匿名只看公开内容（T0）；个人数据一律 403 |
| **管理数据** | **只在本机** | 本机 `8083`（开发者模式）/ `8080`（表单服务）/ 命令行工具 |

**为什么不做公网管理界面**（记下来，免得以后反复讨论）：
公网可写就要有身份验证。要挂 **Cloudflare Access** 需要「自有域名 + 面板启用 Access」，
而当前账号**名下 0 个域名、Access 未启用**（实测）。没有 Access 这一层，
唯一门禁就是应用自己的口令 —— 而那可写界面能改的是**真实数据库**，
风险等级与"公网只读"完全不同。所以先把管理留在本机；等你哪天加了域名并启用 Access，
随时可以升级（见 §4）。

**这条决定不是靠"我们没提供写入口"来保证的**，而是三层强制的（每层都有回归断言）：

1. **端口白名单**：`ops/cf_tunnel.py` 只允许把 `8082` 指向隧道；`8083`（可写）/
   `8081`（控制台）/`55432`（数据库）**一律拒绝**（实测 `start --port 8083` 被拒）。
2. **本机服务只绑回环**：实测 `8082`/`8083`/`55432` 全部监听在 `127.0.0.1`，
   没有 `0.0.0.0`。
3. **数据库只读事务**：实测从**公网**发 INSERT / DELETE / UPDATE / DDL 四条写尝试，
   **全部被拒且库里零残留**（探测行 0、`probe_table` 不存在）。
   这一条最重要 —— 前两层是"没提供入口"，这一层是"**提供了入口也写不进去**"。

**匿名访客能看到什么**（这是实测结果，不是承诺）：

| 能看到 | 看不到（返回 403「权限不足」） |
|---|---|
| 首页公开概览：**123 人才 / 690 岗位 / 151 职业 / 79 码表 / 587 码值 / 176 字段 / 50 维度** | 人才库、真实案例、质量页、职业库、匹配、血缘、扩展 |
| 数据目录、表结构、检索、分析、可视化、只读 SQL 控制台 | 任何单表数据页（含加密身份表）、任何字段页 |

一句话：**"有多少"公开，"具体是谁"要登录。**

## 2. 日常操作（三条命令）

```powershell
cd D:\wbo-workspace\medtalent-db

python ops\cf_tunnel.py status   # 看：隧道进程在不在 + 从公网验一次能不能打开
python ops\cf_tunnel.py url      # 取：当前公网地址（重启后会变！）
python ops\cf_tunnel.py stop     # 关：紧急下线（切断公网入口）
```

要重新开（地址会变）：

```powershell
python ops\cf_tunnel.py start
```

> **下线只切断公网入口**，本机 `8082` 仍在跑——那是正常的，你自己还能在本机看。
> 想连本机也停掉：`Get-Process python | Where-Object {$_.Id -ne $PID} | Stop-Process`
> （会把所有 python 一起停，慎用）。

## 3. 三个必须知道的限制（都实测过）

| 限制 | 后果 | 应对 |
|---|---|---|
| **地址每次重启都变** | 不能把地址写进任何文档/名片 | 每次用 `cf_tunnel.py url` 现取 |
| **挂不了 Cloudflare Access** | 没有"邮箱白名单"这类门禁；唯一的门是应用自己的登录 | 见 §4 升级路径 |
| **没有可用性保证** | Cloudflare 官方明确说免账号隧道不保证可用 | 只用于演示/自用；真要长期跑就走 §4 |

还有一条：**隧道随机器/登录会话结束而断**。Windows 上把它做成系统服务需要管理员权限
（本机没有），所以现在只能手动开。

## 4. 想升级成"固定域名 + 邮箱白名单"（可选，需要你操作）

当前**不需要**做这一步 —— 因为已按 §1.1 决定"公网只读、管理在本机"。
但如果你以后想在**外面管理数据**，或者想要**固定不变的地址**，就需要下面两件
**必须由你操作**的事（我无法代替你登录 Cloudflare、也无法替你买域名）：

### 第一件：把一个域名托管到 Cloudflare
1. 注册/登录 <https://dash.cloudflare.com>
2. 买一个便宜的域名（或用手上已有的），在 Cloudflare 里 "Add a site"
3. 到你的域名注册商那里，把 **NS（名称服务器）**改成 Cloudflare 给的两个
4. 等生效（几分钟到几小时）

> 免费版够用。实测你账号当前 **0 个域名**，所以现在还做不了这一步。

### 第二件：启用 Cloudflare Access（Zero Trust）
1. 面板左侧进 **Zero Trust**
2. 选 **Free** 计划（50 个席位以内免费；建组织时要填付款信息，但不扣费）
3. 点 **Enable Access**
   > 实测你账号当前 **Access 未启用**（API 返回 `access.api.error.not_enabled`），
   > 所以现在也做不了这一步。

做完这两件告诉我，我再改造成：
- **Named Tunnel**：地址固定（例如 `talent.你的域名`），不再每次变
- **Access 策略**：只有你指定的邮箱能进（`Allow → Include → Emails`）
- 那时就能安全地把**管理界面**（`8083`）也挂上去 —— 现在**绝对不行**

## 5. 为什么"现在这样暴露"是可以接受的

因为它满足三个条件（每条都有对应的回归断言，不是我说了算）：

1. **公网侧只暴露只读进程**。可写进程 `8083`、控制台 `8081`、数据库 `55432`
   **一个都没暴露**；`cf_tunnel.py` 的端口白名单写死在代码里，实测 `start --port 8083` 被拒。
2. **匿名在数据库层也读不到敏感列**。不是"页面上藏了一下"：
   匿名角色直接连库也读不到 `person.person_id`、`person.subject_code`、
   `person_pii`、`access_log`、列级剖析快照 —— 这是 PostgreSQL 的列级授权在拦。
3. **内容层实测无识别标记**。匿名能打开的每一个页面都扫过：
   真实姓名、`per_real_` 编号、`MT-REAL` 档案号、手机号/邮箱形态 —— **一个都没有**。

这三条由回归套件 **第 21 套「公网暴露面」**（56 项断言）持续盯着：
将来谁改了页面、动了权限，只要破坏了这三条，回归立刻红。

## 6. 出问题怎么办

| 症状 | 先做什么 | 再做什么 |
|---|---|---|
| 打不开公网地址 | `cf_tunnel.py status` | 进程不在就 `start`；地址变了就用新地址 |
| 页面 500 | 看本机 `http://127.0.0.1:8082` 是否正常 | 本机正常=隧道或 Cloudflare 侧问题；本机也 500=程序问题，跑 `python ops\tests\run_all.py --fast` |
| 怀疑泄露 | **立刻 `cf_tunnel.py stop`** | 再跑 `python ops\cf_preflight.py https://<地址>` 逐页看匿名能拿到什么 |
| 想看谁访问过 | 打开 `/audit`（需登录）或查 `mt.access_log` | 数据库层的连接日志在 `.tools\pgdata\server.log` |

**审计记了什么**（需求①的交付）：谁（`actor`）、以什么等级角色（`actor_role`，**数据库认定、不可伪造**）、
对哪个页面/对象、什么动作、读到多少行、什么时候。数据库层另有连接日志
（哪个账号、从哪、哪个应用、连上/断开）。

## 7. 凭据放在哪（不要在仓库里放任何凭据）

```powershell
python ops\env.py status    # 只看有没有配、多长（**从不显示值**）
```

| 名称 | 用途 | 状态 |
|---|---|---|
| `GITHUB_TOKEN` | 推送代码到 GitHub | 已配置（用户级环境变量） |
| `CLOUDFLARE_API_TOKEN` | 调 Cloudflare API | 已配置（**建议换成最小权限的**：见下） |
| `CLOUDFLARE_ACCOUNT_ID` | 账号标识（不是密文） | 已配置 |
| `CLOUDFLARE_TUNNEL_TOKEN` | 已建隧道的运行令牌 | 未配置（改用 Named Tunnel 时才需要） |

**安全提醒**：用户级环境变量是**明文**存在注册表里，该账号下任何程序都能读到。
它比"写进文件"好（不会进 git、不会被打包），但不等于加密存储。

**关于那个 Cloudflare token**：它当前挂着 300+ 个权限、范围是 `账号:*`（账号级全权限）。
建议重建一个只有这三项的：
`Cloudflare Tunnel: Edit`、`Access: Apps and Policies: Edit`、`DNS: Edit`（限到具体域名）。
