# 08 · 实施计划与任务分解

> **Goal**：建成一个结构化、高可扩展、可溯源的医学生人才信息库，先跑通"岗位侧 → 人才侧 → 匹配"闭环。
> **Architecture**：L0 原始层（只增不改）→ L1 规范层（PostgreSQL 类型化表）→ L2 语义层（词表/字典/派生）→ L3 服务层（匹配/分析/报告）；治理面贯穿四层。
> **Tech Stack**：PostgreSQL 16 + pgvector；DuckDB + Parquet；dbt-core；Python 3.12；CSV/JSON-LD 作为字典交付格式。
> **Spec**：`docs/00-实施方案总纲.md`（总纲）、`docs/01-数据模型设计.md`（结构权威）、`docs/03/04/05/06/07`（分册）。

**累计 20 个只在真库/测试中暴露、静态校验挡不住的问题**（前 16 个见上一节，本轮新增 4 个）：

17. `sync_event.event_id` 用**对方事件号当全局主键** → 跨来源复用编号被 `ON CONFLICT DO NOTHING` 静默吞掉（事件没入账但身份版本已推进）
18. `crosswalk.crosswalk_id` 用固定值 → 跨轮次 PK 冲突被 `DO NOTHING` 吞掉，映射静默失效
19. `talent_deletion_request.request_id` 当全局主键 → 同类问题（契约本就写的是 personId+requestId 唯一）
20. `sync_event` 唯一约束漏了 `direction` → 入向与出向的同版本同类型事件互相顶掉

另修正两处 outbox 逻辑错误：`claim` 取的是**最大**待处理版本（应按升序取最小）；`consent_change` 未校验「不得携带画像载荷」。

> **本轮的核心教训**：问题 17–19 属同一类——**把外部系统的标识符当成自己系统的主键**。
> 契约里两处都明说了唯一性是"某范围内"的，实现时必须落成对应的局部唯一约束：
> 本地生成稳定 id 作主键 + `UNIQUE(来源, 外部id)`。

> 结论：**静态校验是必要不充分的**。因此每个任务都必须实跑 `ops/tests/` 下的测试文件。

## Global Constraints（所有任务隐含遵守）

1. 所有表建在 `mt` schema；ID 用「前缀_ULID」（前缀见 `docs/01` §6.1）。
2. 所有 L1 表必须携带 12 个公共字段（`docs/01` §3.1），缺一不可。
3. 枚举值一律来自 `code_table`/`code_value`，禁止裸写中文枚举。
4. 新字段必须先登记 `field_catalog` 或 `attribute_definition`，否则不入库。
5. 原始数据（L0）只增不改；解析结果必须可回溯到原文。
6. 对外结论必须能按 `evidence_grade`（A/B/C/D）与 `verify_status` 过滤。
7. 禁止自动化抓取 BOSS 直聘 / 智联 / 前程无忧 / LinkedIn（`docs/03` §2.2）。
8. 每个任务结束必须重跑 `python code\validate_catalog.py .`，0 错误方可提交。
